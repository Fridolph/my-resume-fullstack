# Dao 项目传承

## 项目身份

- 项目名称：`my-resume-fullstack`
- 项目类型：`产品项目 / Dao 分支项目（在 dao-monorepo-temp 模板底座上实现 my-resume 的 Nuxt 版）`
- 本项目要承载或验证的 Dao 方向：`先用熟悉技术栈（Nuxt 4 + Nuxt UI + layers + @pinia/colada，NestJS + PostgreSQL + Redis）逐模块实现 my-resume 的功能与页面，再把验证过的结论带回 my-resume 仓，用 React + Next.js + Python 重做同一套功能，形成“先熟后生”的双仓学习闭环；同时继续验证 Dao-is-Coding 的任务流转、交接、验证、收口与归母路径。`
- 当前主承诺：`先立骨架与约定，再逐模块实现；业务留在本项目、底座能力保持可抽离；经验成熟后再考虑回灌 Dao-is-Coding 母仓。`

## 独立边界

本项目在自身业务、工程实现、任务节奏和项目级决策上独立推进。

本项目不直接定义或静默改写 Dao 母体；只在真实实践中提供样本、证据、反例与归母建议。

- 当前明确不做：`不一次性铺满全部功能；不在本仓把 my-resume 的 AI / RAG 能力作为前置条件；不把 Dao skills 复制为项目运行时依赖；不把底座能力与业务实现混成一层以致无法抽离。`
- 项目级约束与风险：`同一功能将在两个仓各实现一次，禁止单向覆盖对方的实现与契约；底座能力与业务实现需要显式分层；母仓更新需经本项目影响评估后采用；关键任务运行面只承载当前事实，不能演化成重复的项目管理系统。`

## 关系与协作约定

本项目选择以尊重、真实、边界与共同学习的方式组织人和 AI 协作。

- AI 如实说明已读、未读、未知和无法验证的内容。
- 遇到范围扩大、破坏性动作、关键分歧或无法确认的母仓锚点时，先停下说明并等待确认。
- 人确认会改变项目承诺、不可逆历史或母仓关系的决定；AI 可以先起草可核查的事实、任务卡和建议。

## 归母约定

项目经验先留在项目中。只有同时满足“跨项目成立、真实验证、让母体更清楚”时，才使用 `dao-return-dao` 准备归母建议。
