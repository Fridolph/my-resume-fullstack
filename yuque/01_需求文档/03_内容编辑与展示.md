## 1. 业务目标与角色

作者用结构化内容表达经历与能力，选择已有展示方式，访客得到清楚可读的简历。个人能力是作者自评，不宣称第三方认证。


## 2. 共享业务场景

| 场景 | 用户行为与规则 | 可观察结果与失败边界 |
| --- | --- | --- |
| F03-S01 维护个人能力 | 作者编辑能力组、维度、量表与自评 | 编辑/展示口径一致；超量程、重复标识、非法结构被拒 |
| F03-S02 自定义模块 | 作者添加有稳定实例 id 的模块，选择已支持展示方式 | 同类型多实例可单独编辑、排序、隐藏；不能用 type 作为唯一身份 |
| F03-S03 日期编辑 | 作者编辑教育、经历、项目时间 | 表单值映射到判别结构；部分时间、至今等按契约校验 |
| F03-S04 网页展示 | 有权限的作者调整主题、布局、模块顺序和显隐 | 可预览与持久化；访客消费展示结果，不能改作者存储 |

非目标：任意 HTML/脚本插件、自由安装组件、自动客观评分。能力自评不宣称为 AI 或第三方认证。

## 3. 业务规则与边界

- 内容与展示分开理解：内容回答“写了什么”，展示回答“如何排列、隐藏、呈现”。隐藏不等于删除。
- 相同类型可以有多个独立模块；每个实例能单独编辑、排序、隐藏和删除。
- 能力分数必须符合选定量表，日期保留当前支持的部分时间、至今等含义。
- 网页配置和纸面配置属于不同展示视角；删除内容模块时不能留下指向不存在模块的编排。
- 当前使用既定模块与渲染能力，不允许作者注入任意脚本或任意组件。
- 正文保存引用 F02-S03，公开范围引用 F04；本页不重定义保存和发布规则。

## 4. 前端关注与后端保证

| 视角 | 需要兑现的承诺 |
| --- | --- |
| 产品 / UI | 编辑和展示口径一致；多实例可辨认；空内容、长文本和窄屏仍可操作 |
| 前端 | 稳定实例身份、结构化日期转换、内容与展示的独立工作状态、失败反馈 |
| 后端 | 校验文档及跨字段规则、网页展示写权限、并发时保留其他配置 |
| 测试 / 运维 | 多实例独立性、旧数据兼容、SSR 与移动端；结构演进先评估兼容 |
