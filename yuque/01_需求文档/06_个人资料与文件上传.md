## 1. 业务目标与角色

登录用户维护自己的展示资料与联系方式，上传头像并确认保存结果。通用上传支持后续内容使用，但不能将“接收文件”解释为“已解析简历”。


## 2. 共享业务场景

| 场景 | 用户行为与规则 | 结果与失败出口 |
| --- | --- | --- |
| F06-S01 本人资料 | 登录用户读改本人用户名、昵称、邮箱、手机、头像 | 身份来自会话；唯一冲突 409；响应不含密码哈希 |
| F06-S02 头像上传 | 用户选图，按 avatar 用途上传后保存资料 | 上传成功不等于资料落库成功；任一步失败都有反馈 |
| F06-S03 通用上传 | 登录用户按用途提交文件 | 校验数量、大小、MIME；记录归属并返回可用 URL |

非目标：背景图、文件内容解析、粘贴简历识别、对象存储、病毒扫描、孤儿文件自动回收。

## 3. 业务规则与边界

- 当前资料目标来自登录身份，不允许表单通过传他人身份来更新其资料。
- 未填写变更项表示保留；支持清空的字段才能主动清空。联系方式唯一冲突必须可反馈。
- 头像先上传再保存资料；前一步成功不代表第二步成功。资料保存失败后允许继续处理。
- 上传校验用途、文件数、大小与允许类型；返回可访问地址。当前文件静态公开，不能宣称为私密附件。
- 上传文件按当前实现做 MIME 与大小校验，未提供内容嗅探、病毒扫描、导入解析、自动孤儿回收。
- 账号角色与密码变更属于 F01，本页资料修改不承担提权或改密。

## 4. 前端关注与后端保证

| 视角 | 需要兑现的承诺 |
| --- | --- |
| 产品 / UI | 可编辑项和清空含义明确；上传中、保存中与冲突分别反馈 |
| 前端 | 只发变更字段；上传和保存分开处理；成功后刷新本人身份展示 |
| 后端 | 目标本人、字段白名单、安全输出、数据库唯一约束、上传归属与边界校验 |
| 测试 / 运维 | 刷新恢复、重复字段冲突、非法文件、第二步失败；目录持久化与公开范围 |

## 5. 验收样本（待执行或核对历史证据）

| 场景 | Given / When / Then |
| --- | --- |
| F06-S01 | 更新昵称和手机 → 刷新恢复，未传字段不变，响应无密码哈希 |
| F06-S01 | 使用已占用的用户名/邮箱/手机 → 冲突有提示，不假报保存成功 |
| F06-S02 | 头像上传成功、资料保存失败 → 提示资料未保存，保留重试机会 |
| F06-S03 | 未登录、空文件、不支持类型、超过大小/数量 → 拒绝且说明原因 |
| F06-S03 | 合法文件上传 → 返回 URL 和元信息；不出现“解析完成”的承诺 |
