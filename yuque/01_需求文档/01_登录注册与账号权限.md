## 1. 业务目标与角色

让已有账号可靠登录，让超管管理账号与授权，让退出、改密和强制下线有明确结果。访客、普通用户、管理员、超管使用同一套身份语言；账号有效与拥有编辑权限是两件事。


## 2. 共享业务场景

目标：作者可靠登录并使用被授权能力；超管管理账号，账号变化能及时使旧会话失效。

| 场景 | 参与者、触发及前置 | 用户可见结果与规则 | 失败出口 |
| --- | --- | --- | --- |
| F01-S01 登录 | 已有账号用用户名或邮箱与密码登录 | 成功取得当前身份；不存在、已删除、密码错误同为凭据错误 | 校验失败 400；凭据错误 401；限流 429 |
| F01-S02 恢复身份 | 登录用户刷新或发起受保护请求 | 服务端读取当前角色权限；已删账号、被撤销会话不能继续使用 | 401 后重新登录 |
| F01-S03 管理账号 | 超管创建、改角色、删除其他账号 | 禁止经接口创建超管；禁止修改本人角色或删除自己，保护超管 | 未授权 403；目标不可用 404；冲突 409 |
| F01-S04 修改密码 | 本人提交旧密码与新密码 | 旧密码正确才修改；成功后旧 token 失效 | 旧密码错误、相同新密码、并发状态变化分别反馈 |
| F01-S05 强制下线 | 超管对允许的 user/admin 操作 | 密码不变，旧会话失效；目标可重新登录 | 禁止越权或操作受保护目标 |

非目标：公开注册、找回密码、多因素认证、刷新令牌、逐设备会话管理。相关角色是 `super_admin/admin/user`；未登录是状态。

## 3. 业务规则与边界

- 账号入口当前是超管创号。公开注册、找回密码没有对应服务闭环；页面中的注册链接不能作为已完成功能的证据。
- 登录成功后能做什么由当前角色、具体权限、资源归属共同决定。不能将“登录成功”解释为“可以编辑任意简历”。
- 普通退出清除当前浏览器会话；改密和强制下线撤销该账号此前的令牌，不等于逐设备管理。
- 用户删除采用软删除；已删除账号不能继续恢复身份。账号资料维护另见 F06。
- 超管查阅关键操作审计沿用 F07-S03；系统留痕沿用 F07-S02。日志、校验、Filter 属于支撑能力，本轮不另开需求页。

## 4. 前端关注与后端保证

| 视角 | 需要兑现的承诺 |
| --- | --- |
| 产品 / UI | 登录失败可理解、可重新输入；风险操作清楚展示目标；不把未开放注册当作可用流程 |
| 前端 | 区分提交中、凭据错误、限流、身份恢复失败；前端权限提示与服务端拒绝都能处理 |
| 后端 | 统一凭据错误、恢复最新权限、保护本人和超管目标、撤销旧会话、必要审计与业务一致 |
| 测试 / 运维 | 验证改密后旧会话、越权直调、异常恢复；跨域及多实例限流另有环境证据 |

## 5. 验收样本（待执行或核对历史证据）

| 场景 | Given / When / Then |
| --- | --- |
| F01-S01 | 同一个有效账号分别使用用户名和邮箱登录 → 均恢复该账号；错误密码与不存在账号不泄露存在性 |
| F01-S02 | 登录后调整角色再请求 → 使用最新角色；会话被撤销后 → 需要重新登录 |
| F01-S03 | 超管尝试创建超管或删除自己 → 拒绝；普通用户直调管理写接口 → 拒绝 |
| F01-S04 | 本人以正确旧密码修改 → 旧令牌失效；旧密码错误 → 不改密码 |
| F01-S05 | 强制下线允许目标 → 密码保持有效，目标可以再次登录 |
| F07-S03 | 普通账号查审计 → 拒绝；超管缺少审计查看权限 → 也拒绝 |

## 6. 当前状态与待确认

登录、服务端会话撤销、用户管理和审计查询已有实现；完整管理界面逐项以任务卡验收为准。公开注册未实现，未来是否开放、验证方式和默认权限均待独立需求评审。

当前用户列表/详情实际上只要求登录，返回联系方式；若产品希望仅管理人员可见，这是一项尚未兑现的授权边界，不能在需求重建时写成已经保证。还需复核登录页的注册/找回密码入口如何表达未开放状态。
