## 1. 业务目标与角色

有编辑资格的作者维护多份简历；创建简单，草稿保存可感知，多窗口修改不能静默覆盖。内部名称用于管理，不等于简历正文中的姓名。


## 2. 共享业务场景

目标：作者维护多份简历，创建成本低，保存不能静默覆盖其他窗口的改动。

| 场景 | 参与者、触发及前置 | 用户可见结果与不变式 | 失败出口 |
| --- | --- | --- | --- |
| F02-S01 创建 | 有编辑资格的作者提交内部名称和最小内容 | 服务端补全完整文档；简历与唯一草稿一起创建 | 非法字段 400；无编辑资格 403 |
| F02-S02 列表与读取 | 登录作者查看本人简历、筛选和翻页 | 列表不返回完整正文；指定草稿只对本人可读 | 他人或不存在资源统一 404 |
| F02-S03 保存 | 作者修改当前文档，持有读取到的 revision | 校验成功且版本一致才写入；冲突保留本地输入 | 无效 400、失效 401、无权 403、不可读 404、冲突 409 |
| F02-S04 重命名 | 作者修改简历内部名称 | 不改正文；不推进正文 revision，当前为最后写入生效 | 目标不存在或非本人 404 |
| F02-S05 删除 | 作者确认删除本人简历 | 简历和草稿物理删除；记录必要审计，不提供回收站 | 取消不发请求；重复删除 404 |

非目标：历史版本恢复、发布快照、实时多人协同、回收站。复制属于后续能力，不能因创建接口可复用就写成已实现。

## 3. 业务规则与边界

- 简历属于作者本人；列表只查本人，草稿不因知道编号就能读取。登录用户可读取本人资源，写操作还要满足编辑资格。
- 创建后具有一份当前草稿。保存的是完整内容文档；“保存成功”以服务端接受为准。
- 多窗口同时编辑时，过时保存应被拒绝并保留失败窗口输入，让用户自行处理冲突。
- 重命名不改变正文；删除是不可恢复的物理删除，无回收站。确认框必须说明影响。
- 发布、默认与分享属于 F04；正文编辑后公开内容如何变化也必须同时阅读 F04。
- 后续如果需要历史版本或发布快照，应先提出新需求，不能把当前草稿版本号解释为版本历史。

## 4. 前端关注与后端保证

| 视角 | 需要兑现的承诺 |
| --- | --- |
| 产品 / UI | 创建、空列表、保存中、保存失败、冲突、删除确认有清楚反馈 |
| 前端 | 独立保存工作副本；保存期间继续输入不丢失；失败可备份、重读或重试 |
| 后端 | 本人归属、合法文档、并发条件更新、删除与审计在同事务内完成 |
| 测试 / 运维 | 两窗口冲突、越权、失败回滚、刷新恢复；硬删除的数据恢复依赖备份 |

| F02-S05 | 用户取消删除 → 无请求；确认且成功 → 列表和读取均不再提供该简历 |
