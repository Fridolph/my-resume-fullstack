## F01 登录注册与账号权限

[需求](../01_需求文档/01_登录注册与账号权限.md) · [前端设计](../02_前端技术设计/01_登录注册与账号权限.md) · [后端设计](../03_后端技术设计/01_登录注册与账号权限.md)

### 实现导读与差异

- [auth.service.ts](../../apps/server/src/auth/auth.service.ts)：登录、签发、身份恢复。
- [user.service.ts](../../apps/server/src/user/user.service.ts)：管理、会话撤销、行锁与审计。
- [账号权限与会话设计](../../docs/server/07_账号权限与会话_设计.md)、[DAO-046](../../dao/tasks/DAO-046-账号与权限域审计.md)：设计依据与验证记录。
- 当前用户 DTO 在 `apps/server/src/user/dto/user.schema.ts`，不能按旧共享契约设计宣称已全部迁到 common。
- 待评审差异：`GET /user`、`GET /user/:id` 当前 Controller/Service 未见额外用户管理授权，实际只有全局登录门；返回含联系方式。产品预期若是管理专用，需要另开修复任务，本轮不修改。

### 测试、运行与复盘

复核：错误账号与密码同为 401；旧 token 在改密后失效；普通用户不能改他人资料/角色；不能创建或删除受保护超管；角色变更审计失败时业务回滚。

证据：`auth/__tests__`、`user/__tests__`、`audit/__tests__/account-audit.integration.test.ts`；DAO-046 留有 HTTP e2e 与真并发对撞未覆盖说明。部署时核对反代 IP、JWT/CORS 和多实例限流；本轮只记录检查项。

学习题：为什么权限不放进 JWT？如果 token 没过期，改角色如何生效？账号查询的“已登录”与“可管理用户”是否等价？

## F04 简历发布与分享

[需求](../01_需求文档/04_简历发布与分享.md) · [前端设计](../02_前端技术设计/04_简历发布与分享.md) · [后端设计](../03_后端技术设计/04_简历发布与分享.md)

### 实现与验收

入口：[share.controller.ts](../../apps/server/src/share/share.controller.ts)、[share.service.ts](../../apps/server/src/share/share.service.ts)、[share.types.ts](../../apps/server/src/share/share.types.ts)、[共享管理响应](../../packages/common/src/share.ts)、两端 `apis/share.ts`、admin `pages/shares/index.vue`。

设计与证据：[分享设计](../../docs/dev/13_分享链接_设计.md)、[DAO-050](../../dao/tasks/DAO-050-分享链接与访问埋点.md)；`share/__tests__` 覆盖期限、列表、sink 与 DI，`resume.service.test.ts` 包含取消发布撤销断言。

复核：取消发布再发布，旧 token 仍失败；到期边界前后结果正确；禁止 PDF 的链接直调下载也失败；改备注不改变授权；他人不能管理链接；统计故障不阻断阅读。

DAO-050 记录 Owner 实看通过、server 119 项单测及两端构建；独立“创建→过期→撤销→PDF”自动 HTTP 全链路未由 AI 跑过。完整 IP/UA 有记录，90 天是设计保留口径，自动清理机制需另核实；不宣称已匿名化或已运行保留任务。生产前需复核隐私、反代 IP、多实例限流与日志 token 暴露面。

学习题：为什么“读取时检查未发布”不足以满足“取消发布后旧链接永久失效”？
