## 1. 场景与职责

引用需求中的 F06 场景；这里只展开页面、交互和请求设计，不重新定义业务规则。范围为当前 Nuxt 4 实现，Next.js 迁移另行设计。

## 2. 当前方案

- admin `/settings/user`，`apis/user.ts` 负责本人资料调用；头像消费通用上传接口。
- 区分资料加载、上传中、保存中、冲突与重试；字段错误回填对应控件，成功后刷新身份显示。
- 更新只提交变更字段；未传保留，只有支持 null 的字段才能清空，邮箱不能自行按 null 发送。
- 上传/资料保存是两个请求；第二步失败保留用户可重试状态。API 支持多文件，业务界面通常引导一次一个。
- 需补 Owner 桌面/移动实看，不能由 typecheck/build 代替。

## 3. 分步失败恢复

读取本人资料 → 编辑字段 → 如有新头像先上传 → 使用新 URL 更新资料 → 刷新身份展示。上传失败不提交无效地址；资料更新失败不清空用户输入或显示整体成功。

手机号前端采用严格工具校验，服务端接受范围不同，属于当前实现差异；不能只因字段名相同就宣称校验完全共享。清空与缺省必须按 API 中字段规则处理。

## 5. 验证与影响范围

需求页的验收样本为共同基线；机器检查覆盖类型、构建及已有自动化测试，Owner 另验桌面/移动关键路径。历史执行证据见实现导读，本文不宣称已执行。仅样式变更先核对 UI/前端/测试；若改变请求、权限、结构或恢复语义，需同步 API 与后端评估。
