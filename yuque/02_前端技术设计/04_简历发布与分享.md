## 1. 场景与职责

引用需求中的 F04 场景；这里只展开页面、交互和请求设计，不重新定义业务规则。范围为当前 Nuxt 4 实现，Next.js 迁移另行设计。

## 2. 当前方案

- 入口：公开 `/`、`/resume/:id`、`/share/:token`；作者列表的发布/默认/分享操作；admin `/shares`。
- 共享弹层表达有效期、备注、PDF 权限、AI 配额；二维码与复制指向实际 `/share/:token`，不是旧设计的 `/s/:token`。
- 访客页区分过期、撤销、未发布等提示，显示 noindex；Toast 表达采集告知，不能写成已取得同意。
- 发布管理页包含筛选、分页、详情统计、元信息编辑、撤销确认；变更后刷新列表和详情，状态优先级由服务端决定。
- 公开 SSR 页面必须 await 数据后决定 404；不能仅画空状态却返回成功 HTTP 状态。

## 3. 页面与接口串联

作者发布 → 必要时设默认或创建分享 → 复制 /share/:token → 访客 SSR 读取。取消发布后同时刷新简历状态、分享列表和详情，不能仅本地隐藏按钮。

分享元信息的编辑与访问授权分开；当前 UI 有 AI 配额字段，不代表对话入口可用。默认首页多作者选择与并发唯一性见后端设计的缺口记录。

## 5. 验证与影响范围

需求页的验收样本为共同基线；机器检查覆盖类型、构建及已有自动化测试，Owner 另验桌面/移动关键路径。历史执行证据见实现导读，本文不宣称已执行。仅样式变更先核对 UI/前端/测试；若改变请求、权限、结构或恢复语义，需同步 API 与后端评估。
