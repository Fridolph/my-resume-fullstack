## 1. 场景与职责

引用需求中的 F02 场景；这里只展开页面、交互和请求设计，不重新定义业务规则。范围为当前 Nuxt 4 实现，Next.js 迁移另行设计。

## 2. 当前方案

- 路由：web `/my-resumes`、`/my-resumes/draft/:id`；admin `/resume`、`/resume/new`、`/resume/:id/edit`。
- F02-S02：列表的分页、搜索、发布筛选、排序进入 query key；操作后刷新或失效相关缓存，不能只改当前一行导致统计错误。
- F02-S03：区分服务端基线与本地工作副本。状态为 `idle/loading/pending/saving/saved/error/conflict`；保存期间继续输入不能被旧响应覆盖。
- web 当前防抖 2500ms；保存使用 JSON 快照校验与提交，避免将响应式代理直接交给克隆逻辑。generation 用于忽略过时请求结果，saving 避免同窗口重叠提交。
- 401 提示重新认证；409 停止自动保存，允许备份后重新读取；网络/校验失败保留输入，支持明确重试。离页或关闭窗口时提示未保存内容。
- F02-S05：二次确认要标明不可恢复，成功后刷新列表并清理无效选择。桌面/移动端分别验收。

## 3. 请求与恢复约束

读取草稿建立服务端基线 → 编辑独立工作副本 → 防抖触发完整快照保存 → 成功更新基线。输入期间不可用旧响应整体重置工作副本。页面列表和编辑器各自的请求状态不能互相冒充。

409 是需要用户处理的版本冲突；不自动拉新版本并覆盖重试。401 引导重新登录；网络超时先核对服务端是否接受过请求。源码与复核用例见实现导读。

## 5. 验证与影响范围

需求页的验收样本为共同基线；机器检查覆盖类型、构建及已有自动化测试，Owner 另验桌面/移动关键路径。历史执行证据见实现导读，本文不宣称已执行。仅样式变更先核对 UI/前端/测试；若改变请求、权限、结构或恢复语义，需同步 API 与后端评估。
