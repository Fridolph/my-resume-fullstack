## 1. 场景与职责

引用需求中的 F03 场景；这里只展开页面、交互和请求设计，不重新定义业务规则。范围为当前 Nuxt 4 实现，Next.js 迁移另行设计。

## 2. 当前方案

- 页面负责选择简历；编辑器负责工作副本；展示注册表按模块类型分派组件，稳定实例 id 用于编排。
- `packages/common` 放文档校验和纯转换，`packages/ui` 放共享编辑/展示能力，各应用 layer 保留业务 API 与身份判断。
- UI 需覆盖空模块、重复类型、多实例、超长文本、嵌套富文本、未知旧数据，以及三档风格与窄屏可读性。
- F03-S04 与正文保存是不同入口；展示保存失败时应可见且保留本地选择，不能把 localStorage 成功等同于后端持久化。
- 日期界面不能直接用普通文本框覆盖结构化日期对象；字段转换通过既有统一组件/工具完成。

## 3. 模块边界与联动

内容编辑复用 F02-S03 的保存链路；展示配置使用独立 display 请求。新增模块需同时核对编辑器、展示注册表、排序显隐与纸面渲染，不因组件能够显示就宣称全链路完成。

仅颜色和间距变化由 UI、前端、测试确认；若增加内容结构或改变保存含义，先更新共享需求，再评估后端、契约与旧数据兼容。

## 5. 验证与影响范围

需求页的验收样本为共同基线；机器检查覆盖类型、构建及已有自动化测试，Owner 另验桌面/移动关键路径。历史执行证据见实现导读，本文不宣称已执行。仅样式变更先核对 UI/前端/测试；若改变请求、权限、结构或恢复语义，需同步 API 与后端评估。
