## 1. 场景与职责

引用需求中的 F01 场景；这里只展开页面、交互和请求设计，不重新定义业务规则。范围为当前 Nuxt 4 实现，Next.js 迁移另行设计。

## 2. 当前方案

- F01-S01：管理端 `/login` 与 web 登录弹层提供输入、提交中、字段错误、凭据错误、限流反馈。重复点击不应重复提交。
- F01-S02：身份展示使用恢复后的资料；页面/按钮权限用于交互提示，最终以 API 授权结果为准。401 与网络故障不能展示为同一种登录失效。
- F01-S03～05：管理操作应展示目标、风险、提交结果；当前存在接口不能证明管理 UI 已完成，角色调整界面仍需按任务卡单独验收。
- 技术视图：认证相关逻辑位于两端各自的 app 目录；页面组合表单与认证状态，API 层消费统一响应。跨端共享登录还需按部署域名验证 Cookie/令牌策略，不能由本地成功推断。
- UI 复核：键盘提交、错误聚焦、窄屏布局、退出后返回受保护页、token 失效后保留用户必要输入。

## 3. 当前文件与请求顺序

- admin：[登录页](../../apps/admin/app/pages/login.vue)、[登录表单](../../apps/admin/app/components/auth/LoginForm.vue)、[会话状态](../../apps/admin/app/composables/useAuthState.ts)。
- web：[登录弹层](../../apps/web/layers/11-public-resume/app/components/resume/ResumeAdminLoginModal.vue)、[会话状态](../../apps/web/app/composables/useAuthState.ts)。
- 认证代码当前位于各端 app；web 的旧形状映射与 admin 的 BackendIdentity 保持独立，未进行统一迁移。
- 提交凭据 → 登录 API → 保存 token Cookie 与身份状态 → 刷新/SSR 以 info 恢复身份。Cookie 可被客户端脚本访问，不描述成 HttpOnly 会话；Cookie 保存期不替代 JWT 有效期。
- generation 使退出/重新登录后的旧异步响应失效；401 清身份，其他错误保留服务故障含义。
- 登录表单仍显示注册与找回密码链接，但后端没有相应流程；作为界面差异待评审，不能写成已上线能力。

## 4. 账号审计视图

- admin `/audit` 使用筛选、分页、详情展示已定义动作与资源；无权限时不提供入口，API 仍需拒绝直调。
- `useAuditLog` 与 API/标签配置分开；空结果、加载失败与权限不足分开表达。
- 排错信息可提供 traceId，避免要求用户复制含 token 或整份正文的网络请求。

审计查询引用 F07-S03，业务留痕引用 F07-S02；请求日志仅作为排错支撑，本轮不拆基础设施设计页。

## 5. 验证与影响范围

需求页的验收样本为共同基线；机器检查覆盖类型、构建及已有自动化测试，Owner 另验桌面/移动关键路径。历史执行证据见实现导读，本文不宣称已执行。仅样式变更先核对 UI/前端/测试；若改变请求、权限、结构或恢复语义，需同步 API 与后端评估。
