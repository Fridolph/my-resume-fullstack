## 文档责任与使用方式

- **共享需求**记录用户目标、场景、规则、失败和验收；产品、UI、前后端、测试和运维共同评审。
- **角色设计**只展开本角色职责；接口文档记跨端输入输出，实现导读连接真实文件与证据。
- **当前事实**来自源码及原任务卡；源码存在、测试文件存在、Issue 关闭、产品验收和正式发布分别判断。
- 本套内容为“已有实现的文档重建，待 Owner 复核”，不补写虚构的历史需求评审或 Sprint。
- `yuque/` 是交付阅读源，[docs](../docs/README.md) 保留原始设计/学习记录，[dao](../dao/CURRENT.md) 保持任务状态事实源。Owner 与 AI 维护 Markdown，语雀只同步已审阅版本；后续若改变主编辑端需明确同步责任。
- 每次变更先改场景，再判断各角色需修改、需知会或无影响。颜色调整通常影响 UI/前端/测试；请求时机改变要核对契约，数据结构改变还需核对持久化，不能一概当作仅前端改动。
