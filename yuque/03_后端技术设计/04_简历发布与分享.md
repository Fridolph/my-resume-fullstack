## 2. 当前方案

- `Resume.publishedAt/isDefault` 控制作者级公开；`ShareLink` 保存 token、expiresAt、revokedAt/reason、label/note、allowPdf、aiQuota/aiUsed。
- token 使用随机字节生成；公开分享读与 PDF 各有限流。`today` 按 UTC 当日 23:59:59.999，不按浏览器本地午夜。
- 当前仅浏览与 PDF 事件接入 `ShareEventSink`。配额字段已存在，不代表 AI 对话或配额扣减执行器已完成。

```text
F04-S01 取消发布：
校验作者编辑资格 → 事务内查本人简历 → publishedAt 置 null
若原为默认则清掉默认 → 批量写未撤销链接的 revokedAt/reason=unpublished
同事务写发布审计 → 提交
重新发布只打开简历公开状态，不清理旧链接的撤销状态

F04-S04 访问分享：
校验 token 形状并限流 → 查链接
不存在 / 已撤销 / 已过期 / 作者不再公开或账号无效 → 对应拒绝出口
通过后读公开文档 → 尽力记录访问时间与浏览事件 → 返回 { draft }
下载分支额外检查 allowPdf → 渲染成功后记录下载事件 → 返回 PDF 字节
```

## 3. 默认展示的实现缺口

业务意图是本人最多一份默认。当前 setDefault 在事务里先清其他默认再设目标，未建立并发唯一性的数据库约束，Service 注释承认并发可能出现多份；不能写成强唯一保证。

findPublishedDefault 只筛已发布、默认且账号有效，未指定站点作者也无确定排序；多作者各自有默认时首页选择不明确。两项都需要单独需求/技术评审，本轮只记录。

## 4. 运行边界

today 按 UTC 当日末尾；过期检查与撤销持久化语义不同。浏览/PDF 事件尽力记录，不能与关键发布审计的事务承诺混用。完整 IP/UA 的保留/清理和多实例限流仍需部署证据。
