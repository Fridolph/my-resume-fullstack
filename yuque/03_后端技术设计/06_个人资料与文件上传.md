## 2. 当前方案

- `GET/PATCH /user/me` 的目标 id 来自认证身份；与管理路由 `/user/:id` 分开，Service 复用 update 的权限规则。
- `SAFE_USER_SELECT` 明确响应字段；用户名/邮箱/手机唯一性由数据库约束兜底，全局 Filter 映射 409，预查不能代替并发约束。
- `/upload/files` 使用 multipart 字段 `files`，purpose 默认 `resume-asset`；单文件 5 MiB、单次至多 10 个，允许 png/jpeg/pdf/md/doc/docx。
- multer 限制接收大小，Service 校验 MIME/大小，文件名由 UUID 和 MIME 映射生成；当前未见内容嗅探，不能宣称文件内容已鉴定。
- 文件按 `purpose/YYYY/MM/uuid.ext` 存储，UploadedFile 记录 ownerId；静态 URL 公开读取，不能当私有文档下载系统。

## 3. 文件与数据库的一致性

文件写盘与资料 PATCH 分属两个请求，普通数据库事务无法回滚已完成的文件上传。当前可留下未被引用文件；自动清理与失败补偿不能写成已实现。

UploadedFile 记录归属与用途，静态 URL 当前公开。MIME 白名单不等于内容鉴定，业务不能据此承诺私密下载、导入解析或恶意文件检测。
