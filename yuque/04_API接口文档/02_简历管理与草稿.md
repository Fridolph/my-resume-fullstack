# F02 简历管理与草稿接口

日期：2026-11-03。基线：`dev@9367c32`。以下为当前源码整理的 Markdown 接口说明；示例均为合成数据，未在本轮发送请求。通用包装和全量路由见 [API 总目录](00_接口目录与交付约定.md)，业务语义见 [需求](../01_需求文档/02_简历管理与草稿.md)。

## 1. 来源、鉴权与响应

输入及响应类型见 [document.ts](../../packages/common/src/resume/document.ts)，授权及状态变化见 [ResumeService](../../apps/server/src/resume/resume.service.ts)。本组全部需要 Bearer；读取限本人，写入还要求编辑角色与明确权限。

简历 id 为十进制正整数字符串，经 schema 转 number，上限 2147483647。读取/创建/保存的 data 为 ResumeDraftResponse：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| resume | { id:number, name:string, locale:string } | 简历管理元信息 |
| revision | 正整数 | 正文并发版本，用于下次保存 |
| updatedAt | string | 更新时间，不作并发条件 |
| document | ResumeDocument | 完整内容与展示，不是数据库行 |

## 2. POST /api/resume 创建

成功 HTTP 201（包装中的 code 当前为 200）。name、locale、document 均必填；document 可以是合法稀疏输入，由服务端补全。客户端不能指定 ownerId、revision 或主键。

```json
{
  "name": "全栈工程师简历",
  "locale": "zh-CN",
  "document": {
    "content": {
      "sections": [
        { "type": "profile", "data": { "name": "学习者" } }
      ]
    }
  }
}
```

此例展示最小创建形状，不是完整保存文档。name 与 locale 范围以链接 schema 为准；locale 不是完整语言标签认证。每次成功创建新资源，不具有请求幂等键，超时后先查列表核对，避免重复创建。

## 3. GET /api/resume 列表

可选 query：

| 字段 | 规则 |
| --- | --- |
| page | 转整数，≥1 |
| pageSize | 转整数，1～100 |
| q | trim 后最多 80 字符，空串视为未搜索 |
| published | 仅字符串 true/false；不传为全部 |
| sort | updatedAt/createdAt/name |
| order | asc/desc |

缺省分页/排序由 Service 决定，见 [list schema](../../apps/server/src/resume/dto/resume-list.schema.ts) 与 Service。成功 data 为 items/total/page/pageSize；items 不含正文，不能用列表替代草稿详情。

## 4. GET /api/resume/:id/draft 与 GET /api/resume/default

成功返回 ResumeDraftResponse；default 是当前用户默认草稿读取，仍需登录，不是匿名首页。不可用或他人资源 404，不泄露文档。

## 5. PUT /api/resume/:id/draft 保存

- 接口：PUT `/api/resume/:id/draft`，Bearer token，JSON。
- 前置：本人、具有编辑资格，读取过当前草稿；前端保留工作副本。
- 输入：expectedRevision 为 1～2147483646 整数，document 符合完整 resumeDocumentSchema；不能只传下面省略示意，不能传 ownerId。

```text
{ expectedRevision: 读取时的 revision, document: 当前完整 ResumeDocument }
```

- 输出 data：resume（id/name/locale）、revision、updatedAt、document。
- 响应：HTTP 200；输入 400、身份 401、无编辑资格 403、资源不可用 404、并发 409 / Resume.Draft:conflict。
- 幂等/重试：成功推进版本；不能把 409 自动变成“取新版本再覆盖”。网络超时后结果不明确，先读取核对，不盲目重复提交。
- 事务：所有权、expectedRevision、完整旧 JSON 进入条件更新；影响行数为 0 时回滚。
- 前端恢复：保留输入，提示冲突，允许备份与重读；过时响应不能覆盖后续输入。
- 验收：同版本并发一成一冲突；他人 ID 不泄露文档；冲突后停止其他业务写入。
- 证据：resume.service.test.ts；旧 HTTP 脚本过时，真实并发链路应独立修复后重跑。



可以从上次成功读取的 document 构造完整请求，不能将创建时的空对象直接保存。本文以 text 表示类型形状，避免省略字段的 JSON 被误当作可直接提交样例。

## 6. PATCH /api/resume/:id 重命名

```json
{ "name": "投递版本 A" }
```

只接受 name；成功 data 为 id/name。正文 revision 不变，当前为最后写入生效；与正文保存并发保证不同。成功后更新列表/详情缓存。

## 7. DELETE /api/resume/:id 删除

无业务 body；成功 data 为 id。物理删除，取消确认不发请求，重复删除返回 404；业务删除与必要审计在同一事务。超时先核对资源是否仍存在，不能假报失败后无提示地重复操作。

## 8. 待补验证

输入 400、身份 401、编辑资格 403、他人/不可用 404、草稿冲突 409 分别验证。真实双窗口、HTTP 异常包装、删除后刷新需对应环境证据；旧 resume-http.mjs 使用已移除字段，不能作为当前整链路通过证明。
