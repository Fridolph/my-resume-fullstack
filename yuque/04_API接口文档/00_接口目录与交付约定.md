## 1. 通用契约与授权说明

- HTTP API 全局前缀 `/api`；以下表格列完整路径。页面 `/resume/:id` 与 API `/api/resume/public/:id` 是不同入口。
- 默认要求 `Authorization: Bearer <token>`；只有明确 `@Public()` 的端点匿名放行。文档不保存真实令牌。
- 授权分别看登录、权限/角色、所有权。“本人”不意味着任何登录账号都有写资格，细节以对应 Service 为准。
- 普通成功 JSON：`{ code, data, message, timestamp, traceId? }`；失败 data 为 null，可带 errorCode/path。当前成功包装 code 为 200，POST 的 HTTP 状态仍可能是 201。
- 前端 `$api` 可能已解包 data；联调先确认所用封装，不能统一再取一层 `.data`。
- PDF 成功直接为 application/pdf，不包 JSON；失败仍为 JSON 错误。
- 用户/分享记录 id 是字符串，简历 id 是正整数；不能把所有 `:id` 都用同一校验。
- timestamp 是响应生成时间，revision 是正文并发版本，二者不能互相替代。

schema 是输入字段、缺省值、可空性和范围的主要依据；TypeScript 响应 interface 只有编译期约束，不代表响应已执行运行时校验。

### 3.2 F06-S01 修改本人资料

- 接口：PATCH `/api/user/me`，Bearer token，JSON。
- 输入：username/nickname/email/phone/avatar 至少一项；username 按 schema 转小写；nickname/avatar 可 null；phone 空串或 null 清空；email 可省略但不能以 null 清空。
- 示例（合成数据）：

```json
{
  "nickname": "学习者",
  "phone": null
}
```

- 输出 data：id/username/nickname/email/phone/avatar/createdAt/updatedAt，无 passwordHash。
- 失败：输入 400、身份 401、唯一冲突 409；errorCode 取 Filter/共享约定，不解析 message。
- 顺序：先上传头像取得 URL，再 PATCH；资料失败不能将上传成功提示当作资料已保存。
- 验收：本人能修改，冲突有反馈，刷新能恢复，真实 token/哈希不进入文档或截图。
- 证据边界：DAO-051 记有类型检查、119 项 server 测试与 admin 构建，真实资料 HTTP 往返仍待补证据。

## 4. 补全 OpenAPI 与联调的后续切片

本轮是 Markdown 草案；下一轮按模块补机器契约，不假设现有生成脚本覆盖所有路由。

1. 选一个场景，对照 Controller、Zod、Service 返回和全局响应确定字段。
2. 补参数、请求/响应 schema、鉴权、Content-Type、成功/失败示例，使用合成数据。
3. 检查 paths、operationId、全部 $ref、required/nullable/default、额外字段和 PDF 二进制。
4. 在确认的测试环境跑 HTTP 正反例，记录环境、日期、提交、结果；未跑写未跑。
5. Apifox 导入先审查差异，外部写入遵守授权；草案不授予外部写权限。
6. 前端按相同场景联调字段、错误、缓存与恢复，把差异写回契约和用例。

现有 docs:resume 仅按脚本实际内容判断覆盖范围；生成成功不替代字段核对。用户及部分分享 DTO 未共享是当前事实，不在补文档时顺手迁移类型。
