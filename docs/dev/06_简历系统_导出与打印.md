# 简历系统 · 导出与打印（PDF 预览 / 编排 / 打印）设计

> 状态：**设计稿，未实现**。本文只定目标、结构、落地步骤与验证计划，不含代码改动。
> 关联：`DAO-027`（简历系统核心设计）、`DAO-028`（个人能力字段与内容结构）、[03_简历系统_核心设计.md](./03_简历系统_核心设计.md)、`apps/admin/README.md` §PDF 预览 / 打印、[06_简历展示_架构设计.md](../web/06_简历展示_架构设计.md)。

## 1. 目标与非目标

**目标**：在 web 端提供一条闭环 —— **用真实的简历数据，在一张 A4 纸上预览、编排、并打印（另存为 PDF）**。

**非目标**（明确不做，避免范围发散）：

- 后端无头浏览器渲染（`apis/pdf.ts` 已预留接口，本轮只保留降级路径 `window.print()`）；
- admin 侧的导出业务页面（当前 `demos/pdf-review` **保持常驻**，作为开发参考）；
- 多处导出、模板市场、分享链接生成等；
- 服务端批量生成（后续 AI 报告等场景再单独评估）。

**边界**：不改 `apps/admin` 的 demos / comps 行为；不改 `ResumeDocument` 契约（导出只是它的又一个消费者）。

## 2. 现状盘点

### 2.1 admin 已有完整 PDF 体系（可直接复用）

```txt
components/pdf/
  PdfPage.vue          A4 纸张：页眉/页脚、landscape 横版、自动页码
  PdfCover.vue         封面原语
  PdfCoverSheet.vue    配置驱动封面（开关/封面图/标题/对齐）
  PdfDocument.vue      容器：收集页 + 自动页码
  DocVnode.vue         容器变体：在渲染阶段注入页码（SSR 即可用）
composables/usePdf.ts  providePdfDocument / usePdfPage / usePdfRenderState
composables/           usePdfExport（后端导出 + print 降级）、usePdfConfig（生效态 config / 编辑态 draft）
layouts/pdf.vue        无后台外壳，浮动 Back / Config / Print（打印时隐藏）
assets/css/main.css    @media print + @page portrait/landscape + .pdf-page 断页规则
apis/pdf.ts            后端导出接口（无头浏览器打开预览页 URL → 等就绪锚点 → 生成 A4 PDF）
types/pdf.d.ts         PdfDocConfig（cover / header / fileName）
```

有两处设计值得保留沿用：

- **`PdfDocVnode` 在渲染阶段注入页码**，所以 SSR 首屏就能带页码，不依赖客户端二次渲染；
- **`usePdfConfig` 分「生效态 / 草稿态」**：Config 抽屉里改的是 `draft`，Save 才写回 `config`，Cancel 直接丢弃 —— 与简历草稿的编辑语义一致。

### 2.2 web 侧已具备的两个关键件

- `ResumeDraftPreview.vue` —— **只依赖 `ResumeDocument`** 的完整渲染器。布局（single / split / threeColumn）、主题（`mode × preset` 调色板 → CSS 变量）、三档风格（`variant` 下发）、区块注册表（按 `type` 映射组件）全在里面。**它天然可以喂给 PDF 页。**
- `ResumeDraftArrangement.vue` + `useResumeReorder` —— 编排组件，改的正是 `display.sections` 的 `order` / `slot` / `hidden` 三个字段，以及 `display.layout.mode`。

### 2.3 缺口

| 缺口 | 影响 |
| --- | --- |
| `pdf/*` 组件与 `usePdf*` 位于 `apps/admin/app/` 之下 | web 无法使用（app 私有代码不跨端），只能复制，违背「同一能力只有一份」 |
| 打印样式只写在 `apps/admin/app/assets/css/main.css` | web 没有 `@page` / `.pdf-page` 规则，打印会丢分页 |
| web 没有独立页面与导航入口 | 用户找不到这条路 |
| web 没有编排 ↔ 打印的联动 | 改了版式无法立刻确认打印效果 |

## 3. 关键决策

| 决策 | 理由 |
| --- | --- |
| **PDF 渲染能力上提到 `packages/ui`** | 这些组件/composable 与业务无关，只依赖 Nuxt 与 Vue —— 按既有判据（能否脱离 Vue）就该待在 layer，而不是某个 app 里。上提后两端共用一份，admin 的 demos 改为引用共享实现后**依然可跑**。 |
| **预览与编排合成一页** | 调版式的动作是"改一下、看一眼"，跳页会打断这个循环。左编排、右 A4 实时预览，改一个字段立刻反映到纸上。 |
| **导出走 `window.print()`（浏览器另存为 PDF）** | 零依赖、矢量清晰、分页由浏览器真实计算；对"一页纸"的简历场景成本最低。后端无头渲染是**一致性更强但更重**的路径，等确有需求（批量、自动化、服务端存档）再接。 |
| **admin 的 demos / comps 原地不动** | 它们是开发期的参考实现（也是本设计的来源）。admin 的业务页面等到 admin 做到这块时再开，届时复用同一套共享组件。 |
| **不改 `ResumeDocument` 契约** | 导出是契约的又一个消费者；为了让打印好看而改数据形状，会污染前两个消费者（展示站、草稿工作台）。 |

## 5. 数据流

```txt
ResumeDocument（@rs/common 契约，真实数据）
   │  useResumeDraft / apis/resume-draft
   ▼
┌───────────────── ResumePrintWorkspace ─────────────────┐
│                                                        │
│  左：ResumeDraftArrangement（复用）                      │
│     改 display.layout / sections.order / slot / hidden  │
│                         │ 同一份 document（单向）        │
│                         ▼                              │
│  右：ResumePrintPreview                                │
│     PdfPage（A4 容器）                                  │
│       └── ResumeDraftPreview（复用渲染器）               │
│                                                        │
│  工具栏：Print（window.print）/ 横竖版 / 页数             │
└────────────────────────────────────────────────────────┘
```

要点：**编排与预览共享同一份 `document`**，预览是它的纯函数式呈现。编排只改 `display`，不碰 `content` —— 这条边界在 `ResumeDraftArrangement` 里已经成立，直接沿用。

## 6. 打印与分页策略

沿用 admin 已验证的规则，并补齐 web 侧：

| 项 | 做法 |
| --- | --- |
| 纸张与边距 | `@page { size: A4; margin: … }`（已有），横版用**命名页** `@page landscape` |
| 断页 | `.pdf-page` 作为分页单元；卡片设置 `break-inside: avoid`，避免条目被拆到两页 |
| 打印时隐藏 | 工具栏、编排区、导航、背景装饰用 `print:hidden` 或 `@media print { display: none }` |
| 颜色保真 | `print-color-adjust: exact`（否则主题色在打印时被浏览器改灰） |
| 页码 | 由 `PdfDocVnode` 在**渲染阶段**注入 → SSR 首屏即有页码，打印不依赖 JS |
| 中文字体 | 依赖系统字体栈；**不嵌入字体**（体积与授权都不划算），接受不同机器略有差异 |

## 7. 落地步骤

每一步都能单独验证，不需要一次做完：

1. **上提 PDF 能力**：`pdf/*` + `usePdf*` 从 `apps/admin` 迁到 `packages/ui`，打印 CSS 抽成 `pdf.css`。验收：两端 typecheck 通过、admin `/demos/pdf-review` 行为与迁移前一致（截图对比）。
2. **web 独立页面**：新增 `/resume/print`，左编排 + 右 A4 预览，喂真实 `ResumeDocument`。验收：改布局/顺序/显隐，右侧立即变化；真实数据（而非 mock）渲染正确。
3. **打印与导出**：接上线工具栏与 `window.print()`，补齐 `@page` / `.pdf-page`。验收：浏览器打印预览分页正确、无 UI 元素混入、主题色保留。
4. **导航入口**：首页 entries + 简历页顶栏；只对已登录且有编辑权限的人显示"编排/打印"入口（与既有的权限判断一致）。
5. **（后续）后端无头渲染**：接 `apis/pdf.ts` 的 `requestPdfExport`，用 `usePdfRenderState().ready` 作为就绪锚点；下载文件 URL。

## 8. 验证计划

| 类型 | 项 |
| --- | --- |
| 机器验 | 两端 `typecheck`、`lint`；`packages/ui` 不新增第三方依赖（沿用零依赖约定） |
| 结构验 | admin 的 `pdf-review` 页面在迁移前后 DOM 结构一致（证明"上提"没改行为） |
| 意图验 | 桌面 1440×1000 与移动 390×844：编排改动即时反映；移动端不提供编排（只读预览 + 打印提示） |
| 打印验 | Chrome 打印预览：分页正确、无 UI 混入、颜色保留、页码存在；至少覆盖单栏与双栏两种布局 |
| 边界验 | 长内容（经历条目多）跨页时卡片不被拆开；隐藏区块后空白不残留；横版切换后页码仍正确 |

## 9. 风险与未决

| 项 | 说明 | 处理 |
| --- | --- | --- |
| 打印样式跨浏览器差异 | Chrome / Safari 对 `@page` 与 `break-inside` 的支持不完全一致 | 以 Chrome 为准；Safari 记录已知差异，不承诺像素一致 |
| 中文字体 | 不嵌入字体，不同机器字形可能不同 | 接受；如需一致，后续评估子集化嵌入 |
| 移动端打印 | iOS Safari 打印入口弱 | 移动端定位为"只读预览"，打印引导到桌面 |
| 前端打印 vs 后端渲染的一致性 | 两条路径结果可能不同 | 后端渲染接入时以 `usePdfRenderState().ready` 为锚点，并做一次并排比对 |
| 权限 | 编排能力只对管理员开放（当前为 mock） | 沿用既有判断；真正的写入校验仍在后端 |
