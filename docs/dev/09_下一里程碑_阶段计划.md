## 0. 判定口径（为什么这么分档）

四档不是按"工作量"分的，是**按"它会挡住什么"**分的：

| 档位 | 判据 | 一句话 |
| --- | --- | --- |
| **A · 假完成** | 功能看起来有、点了有反应，但**没落盘 / 没接线** | 最贵的一类：它让人误判项目已完成 |
| **B · 上线门槛** | 自己本机跑无害，**一旦给别人看就是事故** | 与"接下来有新想法"直接相关 |
| **C · 需求缺口** | 简历产品该有、现在没有 | 正常排期 |
| **D · 清理债** | 不影响功能，但会持续误导后来者 | 顺手做，不单独开轮 |

> **为什么把"假完成"单列一档**：本仓已经踩过两次同类的坑 ——
> `help.vue` 声称"自动保存（防抖）"而 admin 只有手动保存；`/ai-talk` 摆着四张"计划中"的卡片。
> 它们的共同点不是"没做"，是**看起来做了**。
