# 分享链接与访问埋点（设计）

日期：2026-10-19。状态：**设计待确认，未写代码**。
来源：Owner 2026-10-19 的需求 —— 分享要「做全套」：链接级授权 + 有效期 + 权限位 + 行为埋点 + admin 可查。

## 0. 这不是「加个分享按钮」

| | 现状 | 目标 |
| --- | --- | --- |
| 授权粒度 | **作者级**（`Resume.publishedAt` 一个开关） | **链接级**：每条链接独立有效期 / 可撤销 / 权限位 |
| 期限 | 无 | 有，过期 token 作废 |
| 权限位 | 无 | `allowAi`（预留）/ `allowPdf` |
| 可观测 | 无 | 5 类行为事件 + admin 可查 |
| 收录 | 无控制 | 公开主页可索引；受控分享 `noindex` |

需要 **2 张新表 + 迁移 + 公开读路径改造 + 新页面 + 埋点管道**。

## 1. 数据模型

```prisma
model ShareLink {
  id        String   @id @default(cuid())
  /// URL 里那段。**随机、不可猜**（见 §4 决策 3 的长度要求）
  token     String   @unique
  resumeId  Int
  createdBy String

  /// 到期时间。**最多 now + 90 天**（服务端强制，不只 UI 限制）
  expiresAt DateTime
  /// 主动作废
  revokedAt DateTime?

  /// 预留的 AI 口子：现在只存不用
  allowAi   Boolean @default(false)
  allowPdf  Boolean @default(true)

  createdAt    DateTime  @default(now())
  lastAccessAt DateTime?

  resume Resume @relation(fields: [resumeId], references: [id], onDelete: Cascade)
  events ShareEvent[]

  @@index([resumeId])
  @@index([expiresAt])
  @@map("share_links")
}

/// 访问行为埋点。**匿名、高写入量** —— 与 `audit_logs`（有 actor、强一致）不能混表
model ShareEvent {
  id      BigInt @id @default(autoincrement())
  shareId String
  type    String @db.VarChar(32)

  /// 只放**非 PII** 的结构化信息：如 `{ themeKey }` / `{ targetHost }`
  metadata Json?
  /// 访问者标识（见 §4 决策 2 的隐私处理）
  visitorKey String?
  userAgent  String? @db.VarChar(512)
  ipTruncated String? @db.VarChar(64)

  createdAt DateTime @default(now())

  share ShareLink @relation(fields: [shareId], references: [id], onDelete: Cascade)

  @@index([shareId, type, createdAt])
  @@map("share_events")
}
```

**事件类型**（`type`）：`view` / `pdf_download` / `ai_chat` / `external_click` / `theme_switch`。

### 2.1 「当天内有效」的确切语义（已确认）

「当天内」有两种读法，差别是 24 小时还是到午夜：

- **A（建议）**：到**当天 23:59:59.999（UTC）**。符合「今天之内」的直觉，也便于显示"今天到期"
- B：从创建起 24 小时

**已定 A**：到**当天 23:59:59（UTC）**。`expiresAt` 一律存 UTC（与 `publishedAt` 的零点口径一致）。

## 3. 读路径

```
GET  /s/:token            受控分享（校验 有效期 / 撤销 / 简历仍发布）→ 200 或 404+原因
POST /s/:token/ack        访客在引导页确认"同意记录"后调用 → 写 view 事件
POST /s/:token/pdf        PDF 下载（受 allowPdf 控制）
GET  /resume/:id          公开主页（保持现状：已发布即可读；受 indexable 控制 robots）
POST /resume/:id/pdf      登录态 PDF（不变）
```

**失效原因用 errorCode 表达**（不泄露简历内容，只说明链接状态）：
`Share.Expired` / `Share.Revoked` / `Share.Unpublished` / `Share.Deleted` / `Share.NotFound`。

## 4. 评审：5 处会咬人的地方

### 决策 1：「取消发布 ⇒ 链接失效」—— **已定：物化撤销**

| 方案 | 行为 | 后果 |
| --- | --- | --- |
| **A 派生（建议）** | 读时判断 `publishedAt IS NULL` ⇒ 失效 | **重新发布会复活旧链接**。语义简单、无竞态 |
| B 物化 | 取消发布时把该简历的所有链接写 `revokedAt` | 旧链接**永久失效**，重新发布也不会复活（更安全，但"我只是想改一下再发"的人会被迫重建链接） |

**Owner 2026-10-19 定 B（物化）**：取消发布时把该简历的所有链接写 `revokedAt`，
**旧链接永久失效**，重新发布必须新建链接。

取舍记录：更安全（一条已经发出去的链接不会因为作者"改一下再发"而突然复活），
代价是作者要多一步重建。这与 `allowAi` 预留、链接级授权是同一取向：**默认更保守**。

顺带产生一个产品需求：**发布管理页面**（admin）能看"当前有哪些分享链接、是否生效、
什么时候分享的、埋点数据如何"——否则作者无从知道哪条旧链接还活着。

### 决策 2：改成 Toast **告知** —— 但必须记住它不等于"同意"

**HTTP 请求本身的 IP/UA 在页面渲染前就已经到达服务器** —— 所以如果"加载即写事件"，那么引导页的同意就只是**告知**，不是**同意**。

要让同意真正有意义，只有一条路：**加载时不写任何访客信息**，等访客点"我了解并继续"后，再由前端调用 `POST /s/:token/ack` 写 `view` 事件。

**Owner 2026-10-19 定**：不做引导页（挡住看简历太打扰），改成进入页时弹一次 Toast 告知。

⚠️ **必须记住这个选择意味着什么**：没有同意门，`view` 事件在**页面加载时**就写入 ——
也就是说 **Toast 是"告知"，不是"同意"**，采集是**全量**的。文档与代码注释里都要这么写，
不能反过来宣称"已获得访客同意"。

配套两点：

1. **Toast 每次会话只弹一次**（`sessionStorage` 记一个标记），否则刷一次弹一次，
   既烦人又会让人直接无视
2. Toast 文案要点明**用途与边界**：记录访问基础信息（IP / UA / 浏览行为），
   仅用于**学习与功能展示**，不商用、不做其它用途

### 决策 3：token 强度与速率限制

`token` 是公开端点上的唯一凭证，必须：

- **长度 ≥ 16 字符的 base62/hex（建议 24）**；不用自增或可预测串
- `/s/:token` **必须限流**（复用 B3 的 `@nestjs/throttler`，按 IP），否则等同于允许暴力枚举

### 决策 4：IP / UA 的存储形态 —— **已定：完整存储**

存**完整 IP** 会让匿名埋点变成可识别个人的数据，随之而来的是保留期、删除权、谁能看。

建议折中（够做"是不是同一个人重复看"的分析）：

- `ipTruncated`：IPv4 保留前 3 段（`203.0.113.x`）、IPv6 保留前 4 组
- `visitorKey`：`hash(ip + ua + 每日盐)`，**每天变一次**，因此不能跨天追踪同一个人
- `userAgent` 截断 512
- **保留期 90 天**，过期的 `share_events` 定期清理

**Owner 2026-10-19 定：完整存储**。

> **这是有意采集的可识别信息。** 本项目是学习与功能展示用途：
> 记录完整 IP / UA 是为了演示"分享链接的访问分析"能力，**不用于商业用途**，
> 也不与任何第三方共享。保留期仍按 90 天清理，避免无限累积。
> 若将来用于真实业务，这一处必须先改为脱敏或取得明确同意。

### 决策 5：PDF 与将来的 AI 也要走 token

分享出去的访客没有登录态，而 `POST /resume/:id/pdf` 是登录接口。所以：

- PDF 必须新增 `POST /s/:token/pdf`（受 `allowPdf` 控制）
- 将来的 AI 对话同理走 `POST /s/:token/ai`（受 `allowAi` 控制）

这会把 R1 的范围扩大一点（多一个受控 PDF 端点），但不做的话"分享给没账号的人"就永远只能看不能下。

## 5. 收录（SEO）策略

- `/s/:token`：**始终** `noindex, nofollow`（受控分享不该被搜索引擎收录）
- `/resume/:id`：由 `Resume.indexable` 控制 → `<meta name="robots">` 在 **SSR 阶段**决定（不能客户端才改）
- `robots.txt`：`Disallow: /s/`
- ⚠️ 诚实说明：`noindex` 是对**守规矩**的爬虫的约定，**不是访问控制**。真正的控制只有"token 不可猜 + 有效期 + 可撤销"

**`indexable` 是新增列**（迁移）。建议做成**独立开关**（默认 `false`），不与 `isDefault` 隐式联动 ——
隐式联动会在"切换默认简历"时**静默改变** SEO 状态，那种变化没人会注意到。

## 6. 分四轮交付

| 轮 | 内容 | 出口判据 |
| --- | --- | --- |
| **R1** 数据与读写 | `ShareLink` 迁移 + 建/撤/改期接口（90 天上限、默认 3 天）+ `/s/:token` 读 + 失效原因 + `POST /s/:token/pdf` | 建 3 天链接能读；过期/撤销/取消发布各返回对应原因；PDF 受 `allowPdf` 控制 |
| **R2** 分享入口 | `MySharePopover`：复制链接 + `uqr` 二维码 + 有效期快捷项与自定义 + AI 开关位 + 未发布引导 | 复制与扫码都能打开；超 90 天被拒 |
| **R3** 埋点 | `ShareEvent` 迁移 + `ack` 同意门 + 5 类事件 | 各操作在库中可查；未同意不计入 view |
| **R4** 发布管理页（admin） | 分享链接列表（按简历/状态/是否过期/分享时间）+ 详情（埋点统计）+ 撤销 | 能查到"某条链接被看了几次、有没有下载过 PDF"；能撤销且立即生效 |

## 7. 不做的事

- AI 对话本体（只留 `allowAi` 位与事件类型）
- 分享者的自定义封面 / 密码保护（百度网盘有，本轮不做）
- 跨天追踪同一访客（与 §4 决策 4 的隐私处理冲突）
