# 用户管理查询授权：共享场景与全栈设计

日期：2026-11-06。关联 [#62](https://github.com/Fridolph/my-resume-fullstack/issues/62)、[DAO-053](../../dao/tasks/DAO-053-用户管理查询授权.md)、[F01 需求](../../yuque/01_需求文档/01_登录注册与账号权限.md)。基线 `dev@9367c32`。状态：**候选设计，待 Owner 确认授权规则，未修改运行源码**。

## 1. 目标、边界与当前事实

目标：管理查询他人资料必须有明确管理授权，同时保留每个人读取自己资料的能力。只覆盖 GET /api/user、GET /api/user/:id、GET /api/user/me 的区分，不实现管理页面、不改账号写入、角色预设/seed、数据库或登录方式。

当前 [UserController](../../apps/server/src/user/user.controller.ts) 的 findAll/findOne 未接 CurrentUser，[UserService](../../apps/server/src/user/user.service.ts) 未检查读取权限，SAFE_USER_SELECT 包含邮箱/手机号。findMe 调用 findOne；若直接给 findOne 加限制，会把 /me 也封住。全局 JWT Guard 已恢复身份，但“认证成功”不能替代“可查询他人”。

已有 Settings.Users:view；admin 预设也包含它，且历史库可能残留权限。推荐同时检查 super_admin 角色与 view 权限，以符合体验账号只管理本人资料的边界。该推荐尚不能写成 Owner 已确认规则。

## 2. 共享业务场景

沿用 F01 业务域，补充候选场景编号 F01-S07/S08；确认后同步到需求、角色设计与接口文档。

| 场景 | 参与者/触发 | 可观察结果与不变式 | 失败样本 |
| --- | --- | --- | --- |
| F01-S07 管理查询 | 项目所有者查询账号列表或指定账号 | 推荐要求 super_admin + Settings.Users:view；授权先于目标查找；只返回安全投影，仍排除软删用户 | user/admin 即使带 view 也 403；超管无 view 也 403；未登录由 JWT Guard 401；已授权查不存在/软删统一 404 |
| F01-S08 本人读取 | 任意已登录角色打开本人资料 | 身份仅来自认证上下文，不接受请求指定本人；保留本人安全资料读取 | 账号/会话失效由认证层拒绝；不能用 query/body 中的其他 userId 改变目标 |

两场景返回中都不能出现 passwordHash、sessionVersion、角色关联原始记录等未约定字段。这里的安全投影允许本人/已授权管理员看到联系方式，不等于公开名片数据。

## 4. 前端技术视图

本人资料页继续调用 GET /api/user/me，不把自己的 ID 拼到管理详情端点绕行。现有页面/API 成功响应保持不变。先全仓核对 findAll/findOne 管理调用点；若存在依赖旧授权的真实业务调用，记录并暂停扩大范围，不擅自改成公开字段接口。

管理端目前未交付完整用户管理页面，本次不补 UI。403 表示当前身份无管理权限，不触发退出/登录循环；401 仍沿用既有身份失效恢复。现有请求层是否按此处理在实施时核对；若需改请求层，先说明新增影响范围。

## 5. 后端技术视图

采用现有 Controller → Service → PrismaService，不为两个读操作建立通用 RBAC 框架。授权放在管理 Service 入口，确保非 HTTP 调用也不能省略操作者；本人读取调用内部私有读取方法，复用投影和 404 语义。

```text
ASSERT_CAN_READ_USERS(currentUser):
  if NOT currentUser.roleKeys includes super_admin
     OR NOT currentUser.permissionKeys includes Settings.Users:view:
    FAIL 403, 候选 errorCode = Users.User:viewForbidden

LIST_USERS(usersDto, currentUser):
  ASSERT_CAN_READ_USERS(currentUser)
  构造 deletedAt = null 与现有关键词条件
  按现有分页/排序读取 count 和 SAFE_USER_SELECT
  RETURN items/total/page/pageSize

GET_MANAGED_USER(id, currentUser):
  ASSERT_CAN_READ_USERS(currentUser)
  RETURN READ_ACTIVE_USER(id)

GET_MY_PROFILE(currentUser):
  RETURN READ_ACTIVE_USER(currentUser.userId)

READ_ACTIVE_USER(id): 仅模块内部私有方法
  user = 按 id + deletedAt = null 查询 SAFE_USER_SELECT
  if user 不存在: FAIL 404, Users.User:notFound
  RETURN user
```

认证身份不从客户端 body/query 接收。鉴权层本身可能已查询当前账号，因此“拒绝前不查数据库”的准确含义是**不执行本用例的列表/目标用户查询**。HTTP 非法参数仍经过既有 pipe，授权前参数格式错误可能先返回 400；不在本次改动全局执行顺序。

查询无写入，无新增事务/锁。保留现有 count/list 读取方式和排序，不声称列表总数与结果在并发写入下有严格快照一致性。本次无数据库迁移，也不依赖执行 seed 撤销 admin 旧权限。

## 6. API 契约与兼容

| 操作 | 推荐授权 | 成功与失败 |
| --- | --- | --- |
| GET /api/user | super_admin + Settings.Users:view | 既有查询输入和分页包装不变；无管理权限 403 |
| GET /api/user/:id | 同上，查自己也按管理入口规则 | 既有安全投影；已授权时不存在/软删统一 404；无管理权限 403 |
| GET /api/user/me | 任意有效登录身份 | 既有本人投影；保持声明在 :id 前；认证失效 401 |

候选新增稳定错误码 Users.User:viewForbidden；不复用修改/删除错误码，不把拒绝伪装成资源不存在。响应继续使用项目统一包装和 traceId；不新写第二套响应。

成功响应和请求字段不变，行为兼容性发生变化：普通 admin 和 user 以前可读的管理端点将被拒绝。部署前同步 API 说明和调用方；本人 /me 保持可用。若 Owner 选择 admin 也能读，需要另定可读字段和授权矩阵，不能直接套用本候选。

## 7. 测试与验收计划

| 样本 | 验证重点与预期 | 证据层 |
| --- | --- | --- |
| user/admin × 有/无 view | 列表/详情均拒绝 403；不会开始目标查询或泄露存在性 | Service 单测 + 已确认环境 HTTP |
| super_admin 无 view | 403，证明不是只检查角色 | 同上 |
| super_admin + view | 列表分页/关键词，单个活动用户可查，安全投影不回归 | 单测 + HTTP |
| 无 token / 无效会话 | 认证层 401；不把登录失败混为 403 | HTTP |
| 授权者查不存在/软删 | 同一 404/errorCode | 单测 + HTTP |
| 三种角色 /me | 正常读取本人，路由不被 :id 截获，不被管理授权连带封锁 | 单测 + HTTP |
| 已存在本人资料页面 | 加载仍可用，未引入 403→错误退出循环 | 验证窗口真实页面回归 |

机器检查：新增有意义的 Service 行为断言、必要的 Controller 接线断言、pnpm check、server build。不能只测辅助权限函数而漏掉管理方法入口；响应投影要检查实际 select。HTTP/浏览器由验证窗口在已确认环境执行，记录版本和角色；未执行则如实保留。本任务不创造测试账号、不迁移或 seed 用户库。
