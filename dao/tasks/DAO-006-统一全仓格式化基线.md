## Grill：开工前对齐

- 目标：让全仓文件与**当前** `oxfmt` 版本的格式化结果一致，使 `pnpm format:check` 恢复通过，质量门重新可信。
- 背景证据：2026-10-07 在 DAO-005 中实测，**改动前**的 `pnpm exec oxfmt --check .` 就报 **121 个文件**不合格；仓内既有文件与当前 oxfmt 的期望格式存在系统性差异（引号、分号、Markdown 表格对齐等）。
- 边界：只做格式化，不改任何语义、不改业务逻辑、不顺手重构。
- 不做：不升级或降级 oxfmt 版本（“锁定版本”是 Owner 未选的备选方案）；不借机改 `.oxfmtrc.json` 的规则；不动 `.gitignore` 已忽略的产物。
- 涉及文件 / 模块：全仓（`apps/*`、`packages/*`、`docs/*`、`dao/*` 等），主要是既有文件的格式重排。
- 风险与未知：一次大 diff 会淹没此前的收口历史；若与在做的任务混在同一批改动里，将无法区分“格式”与“语义”。**因此必须在 DAO-005 提交之后再执行。**
- 验收：① `pnpm format:check` 通过；② `pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build` 通过；③ `git diff` 仅含格式变化（人工抽查若干文件，确认无逻辑改动）；④ 在 README 或 `docs/dev/` 记录“格式化基线以当前 oxfmt 版本为准”的结论。
- 第一刀：确认 oxfmt 的实际版本与配置来源（根 `package.json` 声明 `^0.48.0`，需核对 lock 中实际安装版本），再跑一次 `pnpm exec oxfmt --check .` 记录基线数量，然后执行 `pnpm format` 全仓重排。
