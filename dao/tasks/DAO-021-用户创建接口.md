## 目标与边界

本轮完成超管创号 POST /user → 邮箱登录 POST /auth/login → 当前会话 GET /auth/me 的最小闭环。字段校验、权限、密码哈希、用户与角色原子写入及数据库身份恢复属于本轮；其他 CRUD、公开注册、前端、版本化、OAuth、Redis 不属于本轮。

涉及 user、auth、请求上下文、错误码、AppModule、Prisma schema/新增迁移/seed、README 和接口讨论文档。新增三列可空资料；角色仍沿用现有 RBAC 表。Owner 已修改讨论规则并授权实装，AI 不执行数据库操作或验证。

## 已完成

- email 必填唯一并规范化为小写；nickname 可选、2–32 字符，默认“新用户”；password 创号 6–20、登录 4–64 且不 trim。
- id 沿用 cuid，username/phone 从接口移除，旧列暂保留历史数据；roleKey 默认 user，仅允许 admin/user。
- UserCreationGuard 要求 super_admin 和 Settings.Users:create。
- UserService 直接使用 PrismaService，完成角色检查、密码哈希与 nested write；唯一约束冲突由全局 Filter 统一返回，响应排除哈希。
- AuthService.login(LoginDto) 使用邮箱验密；JWT 仅携带 sub 与签发/过期时间，每次按 sub 恢复身份权限。
- Owner 已授权 Passport：新增 JwtStrategy，Guard 继承 AuthGuard('jwt')，AuthService.restoreUser 专注身份恢复；保留公开路由、token 错误码与数据库故障语义，补齐 Express.User 类型及依赖锁文件。
- seed 初始化 super@example.com / Super123!，昵称 super；账号与超管关联在事务中写入，重复执行保留已有密码，不自动恢复软删除账号；旧 admin 账号保留，不再修改其资料或角色。
- 新增邮箱登录与昵称重命名迁移，保留旧用户名/手机号数据；未生成本地 Prisma client。
- 多行 TSDoc 解释设计理由与业务取舍，约定已同步 AGENTS.md 和模块模板。
- 已补充创建与登录的开发顺序、请求执行顺序及首个超管的初始化思路；只准备源码，未在数据库中实际创建 super。
- Owner 授权后端命名调整：目录 `apps/api` → `apps/server`，工作区包名 `@rs/api` → `@rs/server`；同步锁文件 importer、清理脚本和文档路径，源码与本地文件整体迁移。该重命名不改 HTTP `/api` 前缀、数据库结构或业务逻辑；未运行项目验证。
