## 目标与边界

- 目标：用户可在**创建或编辑简历时**自建模块 —— 自定标题 + 自选展示方式 + 自填内容，并与预设模块一起参与**拖拽编排**（顺序 / 栏位 / 显隐）。
- 范围：
  - 契约加 `custom` 分支（`packages/common`）
  - 展示层支持**多实例**（`packages/ui` 的排布与组件注册表）
  - web 草稿工作台 + admin 创建/编辑页都能添加、编辑、删除自定义模块
- 非目标：字段级开关、模块内嵌套、用户自定义 HTML / 组件名、真富文本编辑器（见「待确认 1」）

## 现状分析（已核实）

| 层 | 现状 | 对多实例的影响 |
| --- | --- | --- |
| 契约 | `resumeSectionSchema = discriminatedUnion('type', [7 个分支])`；**每个 section 都带 `base` 的 `id` / `title` / `description` / `icon`** | ✅ `id` 天然就是多实例的身份 |
| 契约的 display | `display.sections.order` **已经是 id 数组** | ✅ **契约字段不用改** |
| 展示配置 | `ResumeDisplayConfig.sections` 的 `order` / `slot` / `hidden` 是 **`ResumeSectionKey[]`（7 个固定 key）** | ❌ 这是唯一装不下多实例的地方 |
| 注册表 | `resumeSectionComponents: Record<ResumeSectionKey, Component>` | ✅ 只需按 `type` 查；`custom` 再由 `view` 分派 |

**结论**：真正的改动是「排布的寻址单位从 **type(Dkey)** 变成 **section id**」，契约只做**加法**。

## 字段修改（契约候选）

```ts
// packages/common/src/resume/document.ts —— 新增第 8 个分支，复用现有 base 与 textItems
z.strictObject({
  ...base,                                    // id / title / description? / icon?
  type: z.literal('custom'),
  data: z.strictObject({
    view: z.enum(['textList', 'richText', 'tagCloud']),   // 有限枚举，首批 3 种
    items: z.array(textItemSchema).max(50),               // 三种 view 共用一种数据形状
  }),
}),
```

**为什么 `items` 三种 view 共用**：`textList` 每项一条、`tagCloud` 每项一个标签、`richText` **每项一段**
（编辑时一个多行输入框，按行拆；渲染时保留分段）—— 契约只有一种数据形状，既省字段又不用为每种 view 写 `superRefine` 分支。

**为什么 `view` 必须是有限枚举**：契约是跨端共享 + `strictObject` 严格校验的；若放开成任意字符串，
web 就必须为"未知 view"做兜底渲染、数据库里也会出现前端认不出的数据（Issue #39 正文已论证）。

## 兼容性分析（改动前必读）

1. **`schemaVersion` 保持 1**：新增分支是**加法** —— 旧文档不含 `custom`，照旧通过校验；无需迁移、无需升版本。
2. **契约的 `display` 字段一个都不改**：它的 `order` / `slot` / `hidden` 本来就是 id，天然支持多实例。
3. **要改的是展示层 `ResumeDisplayConfig.sections`**（key → id）。这是**前端态**（web 存 localStorage）：
   旧数据读取时校验不过 → **回退默认配置**（用户的排布偏好会重置一次，可接受；不做版本迁移，避免过度设计）。
4. **已有文档不受影响**：7 个预设区块的 id 不变，排布改按 id 后依然指向同一批区块；
   详情页的 `toResumeDisplayConfig` 从"id→key 翻译"**简化为直通**。
5. **`toLegacySectionKey` 保留**：它仍负责契约 type → 展示 key（`capabilities` → `skills`）的桥接，与本次无关。

## 程序化伪代码（编辑侧「添加自定义模块」）

```
输入：当前草稿 document、{ title, view, items }
1. 校验输入：title 非空且 ≤ 名称上限；view ∈ 三个枚举；items 去空行、每项 ≤ 单条上限、总长 ≤ 上限
2. 构造 section：{ id: newId(), type: 'custom', title, data: { view, items } }
3. 插入位置：document.content.sections 末尾
4. 同步展示配置：display.sections.order 追加该 id；slot 默认 'main'；hidden 不含它
5. 整体校验：resumeDocumentSchema 解析整份文档（失败 → 拒绝保存并指向具体字段）
6. 保存：走现有 `PATCH /resume/:id/draft`（revision 并发校验）—— **不新增接口**
返回：保存后的 document（含新模块）
```

删除：从 `content.sections` 移除 → 同步从 `display.sections` 的 order / slot / hidden 清理该 id。
编辑：按 id 定位后替换 `title` / `data`（view 可换，items 保留能保留的部分）。
