## Grill：目标、边界与验收

- 目标：管理查询明确授权，普通登录不自动读他人资料；保留所有角色本人 /me 读取。
- 边界：仅用户列表/详情读取授权、内部调用链、安全投影与对应契约/测试。
- 不做：管理 UI、创号/改密等写入、seed/角色预设、数据库/依赖/环境变更、skill 完善或 AI。
- 文件：[设计交接 §8](../../docs/server/10_用户管理查询授权_设计.md#8-涉及文件回退与续跑)；文档与后续源码分阶段变更。
- 风险：admin 预设含 view，单看权限无法隔离体验账号；findMe 复用 findOne，直接加授权会误封本人；收紧授权改变旧客户端可访问范围。
- 验收：角色×权限矩阵、授权前不开始目标查询、/me 三角色正常、安全投影、404/401/403 与 API 同步；机器与真实 HTTP 证据分开。
- 第一刀：确认后先写 Service 拒绝/本人访问测试，再改 Controller 身份接线和 Service 内部读取边界。
- 过门：`需补一问`，只缺 super_admin + view 是否为本轮采用规则。
