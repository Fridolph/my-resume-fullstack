## 为什么要做（事实）

- `/resume` 曾是 mock 驱动的公开预览，后因漂移改为**列表页**（`a515925`），于是**访客没有任何入口**；
- 作者侧"展示哪一份"已由 `isDefault` 回答，但**访客侧没有 URL**；
- 展示层（类型 / 映射 / 区块组件 / 三档风格）已上提 `@rs/common` + `packages/ui`（DAO-034），
  公开页**不需要新写渲染逻辑**，只需接数据与路由。

## 字段修改（契约）

**本轮不需要新字段、不需要迁移。**

- `isDefault` 已存在（迁移 `20261015093000_resume_default`）；
- 公开接口返回的仍是现有 `ResumeDraftResponse`（`resume` + `revision` + `updatedAt` + `document`），
  因此 `packages/common` 的契约**保持不动**。
- 复用 `ResumeDraftResponse` 而非新建 `PublicResumeResponse`：形状完全一致，
  新增类型只会制造两份需要同步的定义。

## 程序化伪代码（后端公开只读）

```
GET /api/resume/published            （@Public，无需 token）
1. 服务端查 resume where isDefault = true 且 workspace.user.deletedAt = null 且 draft 存在
2. 查不到 → 404 RESUME_NOT_FOUND（"还没有设为默认展示的简历"）
3. 查到 → 读该简历的 draft，按 ResumeDraftResponse 形状返回（含完整 document）
   ⚠️ 不做 ownership 过滤：这正是"公开"的含义；过滤条件只有"是否默认 + 账号是否有效"

GET /api/resume/published/:id        （@Public，无需 token）
1. id 参数按现有 resumePrimaryKeySchema 校验（正整数，否则 400）
2. 查 resume where id = :id 且 workspace.user.deletedAt = null 且 draft 存在
3. 查不到 → 404（不区分"不存在"与"别人的" —— 与 DAO-033/§16 的 404 语义一致，避免泄露存在性）
4. 查到 → 返回同一形状

⚠️ 路由声明顺序：`published` 与 `published/:id` 必须写在 `:id/draft` **之前**，
   NestJS 按声明顺序匹配（现有 `default` 路由已有同样的注释与约束）。
```

**为什么不在 `GET /:id/draft` 上加 `@Public`**：那个接口带 ownership 过滤，语义是"我的草稿"；
把公开访问塞进同一路由，会让"谁能读"随调用方身份漂移 —— 两个语义分开路由，权限模型才读得懂。

### 由此确立的配置数据流（重要，别再走反）

```
document.display（作者在别端调过的观感）  ← 渲染基线
        ↓ adopt(display)
useResumeDisplay 的 config（对象引用共享）  ← 设置面板直接改它
        ↓ 工作台自动保存 / admin 整份提交
document.display                            ← 同一条保存路径，无第二套状态
        + localStorage                       ← 用户本机继续调，下次打开还是他调过的样子
```

- `adopt()` 新增在 `useResumeDisplay`：因为 `toResumeDisplayConfig` 对 `layout` / `theme` / `style` /
  `background` 本来就是**引用直通**，所以"共享对象"就等于"改动自动落到文档"，不需要回写逻辑；
  唯一例外是 `sections`（浅拷贝），已显式把 `order` / `slot` / `hidden` 接回文档，否则拖排序与切显隐会丢。
- 上一轮我按"服务端为真源"写的 `useResumeDocumentDisplay` 适配层**方向错误，已删除**。

### ✅ 已修复并定稿：操作按钮用**页面内 sticky 操作条**

**先说结论**：这条路走不通，而且原因是硬性的 ——
把按钮投到布局页头需要"页面具名插槽 → 布局 `<slot>` 转发"，但
**页面组件的根模板不允许写具名插槽**，Vue 编译器直接报：

```
[plugin:vite:vue] Codegen node is missing for element/if/for node.
  apps/admin/layers/11-resume/app/pages/resume/[id]/edit.vue
```

（`<template #header-actions>` 在根层被当成匿名 fragment，于是 codegen 节点缺失。）

**定稿方案**：两个页面各自带一个 **`sticky top-0 z-10` 的操作条**（内容区顶部、
`bg-default/90 + backdrop-blur`），按钮只出现这一次，滚动时始终可见。
不依赖任何布局插槽机制，也不需要 sticky 之外的额外复杂度。
