## 目标

2. 头像走**通用上传接口**（`POST /api/upload/files` + `purpose=avatar`），不为头像另开端点

## 关键决定

| 决定 | 理由 |
| --- | --- |
| 用 `/user/me` 而不是 `/user/:id` | 后者是**管理**接口（要用户管理权限）；"改自己的资料"是每个登录用户的权利 |
| `/me` 路由声明在 `:id` **之前** | Nest 按声明顺序匹配，否则 `me` 会被当成用户 id |
| `PATCH /me` 复用 `UserService.update` | 它内部已有"本人恒可改自己 / 改别人要超管 + 编辑权限"的分支，一份权限逻辑两个入口 |
| `SAFE_USER_SELECT` 常量统一排除 `passwordHash` | 各方法各写 `select` 时漏一处就等于**静默泄露** |
| 服务端手机号规则**比前端宽松** | 前端 libphonenumber 严格校验负责提示；服务端更严会导致"前端放行、提交被拒"，用户无从自救 |
| `findOne` 对"不存在"与"已删除"返回同一个 404 | 区分了就等于告诉对方"这个 id 存在过" |
| 唯一冲突**不预查** | 预查挡不住并发（两人同时改成同一邮箱），交给数据库 + 全局 Filter 转 409 |

## 验收标准

1. `GET /api/user/me` 返回本人资料，**不含** `passwordHash`
2. `PATCH /api/user/me` 能改用户名/昵称/邮箱/手机/头像
3. 用户名/邮箱/手机与别人重复 → **409**，且页面把提示挂到对应字段
4. 头像选中即上传，成功后立即替换并落库
5. `GET /api/user` 与 `/api/user/:id` **不再 500**
