## 目标与边界

Owner 已确认完整删除伪代码；本轮完成 UserController.remove → UserService.remove 的单用户软删除接口。只有同时具备 super_admin 角色和 Settings.Users:delete 权限的操作者可以删除 user/admin，禁止自删与删除任何含 super_admin 角色的目标。

涉及 user Controller、Service、错误码与说明文档；不更改表结构、依赖、seed、角色预设或公共包。资料修改方法的真假值判断已恢复为 !== undefined，以保留已确认的 null 清空语义；其余用户本地修改保留。

## 确认事实与实现

- Schema 跨端共享：Owner 选择暂保留后端本地 Schema，共享包方案仅作讨论记录。
- 删除伪代码：Owner 已确认，Controller 传入认证身份，Service 检查操作者、本人、目标状态和目标角色。
- 条件更新只写 deletedAt，保留角色关联和 username/email 唯一值。
- 不存在或已删除返回 404；预查询后的条件更新未匹配返回 409；成功返回 id、deletedAt。
- updateMany 按唯一 ID 最多修改一行，并附加软删除及角色条件。未来在线角色分配需与删除协调事务/锁，当前不宣称解决跨表角色变更的全部并发情况。
