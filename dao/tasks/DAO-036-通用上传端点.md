## 目标与边界

- 目标：一个**通用**上传端点（不只服务简历），把"上传能力"从"模板遗留"变成"真能用"
- 范围（待设计确认）：
  - 接口：`POST /api/upload`（路径待定），返回上传结果契约（`UploadedFile[]`）
  - 落盘：本地 `/static/upload/`（后期换 S3 只换实现，接口形状不变）
  - 限制：大小 / MIME / 扩展名 / 单次数量
  - 鉴权：走全局 JWT Guard
  - 清理：未使用文件的回收策略（避免磁盘无限增长）
- 非目标：对象存储、AI 解析（属 #38 的上传→分析线）、病毒扫描 / 图片转码

## 设计草案（AI 建议，待 Owner 拍板）

| # | 议题 | 建议 | 理由 |
| --- | --- | --- | --- |
| 1 | 端点与响应 | `POST /api/upload`，FormData 字段 `files`（单/多统一）；响应走现有统一包装，`data` 为 `UploadedFile[]`：`{ id, url, name, size, mime }`；契约类型进 `@rs/common` | 与现有接口同形；两端共用同一份形状（admin 上传、web 展示预览都会用） |

| 3 | 落盘 | 目录 `apps/server/static/upload/<YYYY>/<MM>/`；文件名 `<uuid>.<ext>`（**不用原始文件名**），原始名只存在记录表里 | 防同名覆盖与路径穿越；按日期分桶避免单目录过大 |
| 4 | 静态服务 | Nest `useStaticAssets` 把 `/static/upload/**` 映射到磁盘（`@nestjs/platform-express` 已有，不加依赖）；**公开可读** | 简历封面/头图本来就要公开；若将来有私密文件，再走 `GET /api/file/:id`（带鉴权）另开 |
| 5 | 上限 | 单文件 **5 MB**、单次 **≤ 10 个**；MIME 白名单：`image/png|jpeg|webp|gif`、`application/pdf`、`text/markdown|plain`、Word 两种 —— 与设计 §4 的「pdf / md / word / txt」对齐，且**服务端强制** | 客户端校验只是体验，服务端才是边界 |
| 6 | 清理 | 本轮**只做接口与记录**，孤儿清理留到有需求时（记入未验证边界）；判定依据已具备（记录表 + 引用关系） | 简历域还没有"引用上传文件"的字段，现在做清理没有可判定的输入 |

### 目录 / 桶怎么组织（Owner 提出的问题，结论）

**按"用途"分一级目录，而不是按文件类型；日期做二级**：

```txt
static/upload/<purpose>/<YYYY>/<MM>/<uuid>.<ext>
例：static/upload/avatar/2026/10/7f3c….png
    static/upload/resume-import/2026/10/9a1b….pdf
```

理由（对 Owner 提问的正面回答）：

1. **用途才是"操作单位"**：清理、配额、权限、迁移都按用途发生（"删用户时清掉他的头像"、"简历导入文件 30 天后过期"），
   而"文件类型"几乎从来不是批量操作的单位 —— 按类型分目录，等到要按用途清理时就得全目录扫一遍。
2. **日期二级是运维维度**：单目录几千个文件后 `ls`/备份/同步都会变慢；对象存储的常见做法也是"前缀 + 日期"。
3. **不要按用户分目录**：用户 id 做目录会让"同一用途跨用户统计"变难，且将来换对象存储时 key 结构要跟着用户体系走。
   谁传的由 **DB 记录**（`ownerId`）表达，不由路径表达 —— 路径是存储结构，不是权限结构。
4. **桶（bucket）保持一个**：多桶通常用于"权限策略差异大 / 生命周期规则不同 / 合规隔离"；
   本项目当前都不需要，等真有隔离需求时，`purpose` 一级目录可以平滑变成独立桶（key 不变、只换前缀）。
5. **`purpose` 同时在 DB 里冗余一份**（`uploaded_files.purpose`）：文件系统结构给人看，DB 字段给查询用，
   两者一致由写入路径保证。

### 表结构（草案）

```prisma
model UploadedFile {
  id           Int      @id @default(autoincrement())
  ownerId      String                        // 上传者（User.id）；将来按用户清理的依据
  purpose      String   @db.VarChar(40)      // avatar / resume-import / resume-asset …
  path         String   @db.VarChar(255)     // 相对 static/upload 的路径（不含前缀，便于换存储）
  originalName String   @db.VarChar(255)
  mime         String   @db.VarChar(100)
  size         Int
  createdAt    DateTime @default(now())
  @@index([ownerId])
  @@index([purpose, createdAt])
  @@map("uploaded_files")
}
```
