## Grill：开工前对齐

- 目标：让干净工作区中的 `pnpm typecheck` 与 `pnpm test` 能通过明确的任务依赖获得所需构建产物，不再依赖人工先执行 `pnpm build`。
- 边界：只检查并修复根脚本、`turbo.json` 与受影响 package 脚本之间的构建依赖表达。
- 不做：不修改业务逻辑、测试断言、公共包 API、依赖版本、CI/CD、数据库或 Dao skills；不为此引入新的构建工具。
- 涉及文件 / 模块：根 `package.json`、`turbo.json`，以及调查中确认确有必要的 package 脚本。
- 风险与未知：为 `typecheck` / `test` 盲目依赖完整 `build` 可能掩盖类型问题或增加不必要成本；需要确认 Turbo 当前任务图和 package 导入方式。
- 验收：在清理构建产物后，`pnpm typecheck`、`pnpm test` 均能独立成功；现有 `pnpm lint`、`pnpm build`、`pnpm format:check` 仍通过；变更不触及业务代码。
- 第一刀：读取 `turbo.json`、workspace package 脚本与 `@template/common` 的导出配置，复现并定位 `dist` 缺失的依赖链。
- 过门判断：`可开工`。问题、边界和验收清楚，具体修复点须由任务图证据决定。
