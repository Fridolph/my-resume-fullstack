## 目标

把「分享」从**作者级开关**（`Resume.publishedAt`）升级为**链接级授权**：

1. 每条分享链接有**独立有效期**（默认 3 天，上限 90 天）
2. 可**主动撤销**；简历取消发布时链接失效，且**能分别说明失效原因**
3. 有**权限位**（`allowAi` 预留、`allowPdf`）
4. 记录**访问行为**（浏览 / PDF 下载 / AI 对话 / 外链点击 / 主题切换），admin 可查
5. 受控分享 **`noindex`**；公开主页的收录由 settings 开关控制

## 非目标

- AI 对话本体（只留 `allowAi` 位与事件类型）
- 自定义封面 / 链接密码（百度网盘有，本轮不做）
- 跨天追踪同一访客（与隐私处理冲突，见设计文档 §4 决策 4）

## 为什么值得单独立卡

它需要 **2 张新表 + 迁移 + 公开读路径改造 + 新页面 + 埋点管道**，
且与既有两条约束直接冲突，必须显式取舍：

| 冲突 | 取舍 |
| --- | --- |
| `publishedAt` 是作者级开关，分享是链接级 | 两条路径**都过 `publishedAt`**：链接授权不能绕过"未发布不可读" |
| 埋点是匿名高写入，`audit_logs` 是有 actor 的强一致记录 | **分表**，不混 |
| `noindex` 常被当成访问控制 | 文档里写明它只是对守规矩爬虫的约定，**不是**访问控制 |

## 验收标准（分四轮，见设计文档 §6）

**R1 数据与读写**
1. 建 3 天链接 → 能用 `/share/:token` 读到
2. 超过 90 天被服务端拒绝（不只是 UI 拦）
3. 过期 / 撤销 / 取消发布 / 简历删除 → 各自返回**不同的 errorCode**，失效页分别说明
4. `allowPdf = false` 时 PDF 端点拒绝

**R2 分享入口**
5. 复制链接成功有即时反馈；二维码可扫码打开
6. 有效期四个快捷项 + 自定义，超限被拒
7. 未发布时**不出现**分享入口，改为"先发布"引导

**R3 埋点**
8. 通过引导页确认后才写 `view`（未同意不计入）
9. PDF 下载 / 外链点击 / 主题切换各有对应事件
10. 事件里**不含**简历正文、姓名、手机号、邮箱

**R4 admin**
11. 能按简历 / 状态 / 是否过期筛选分享链接
12. 能看某条链接的事件统计（被看几次、是否下载过 PDF）
13. 能撤销一条链接，撤销后立即不可读

### 修掉的实现缺口（R3 期间发现）

R1 的"取消发布"是**派生式**的（读时判断 `publishedAt IS NULL`），`revokedAt` 从未被写过
⇒ **重新发布会让旧链接复活**，与 Owner 定的"永久死"不符。
现已在 `setPublished(false)` 的**同一事务**里物化撤销，并加了三条测试断言。

## 已定的两个非显然结论

1. **Toast 是「告知」，不是「同意」**：没有同意门，`view` 在页面加载时即写入，采集是全量的。
   文档与代码注释都必须这么写，不能宣称"已获访客同意"。
2. **完整 IP 是「有意采集的可识别信息」**：仅用于学习与功能展示、不商用；
   保留期 90 天。若转真实业务必须先脱敏或取得明确同意。

## R3 之前的两个语义修正（2026-10-19 讨论）

1. **`ShareLink.revokedReason`**：`revokedAt` 现在被"作者主动撤销"与"取消发布批量撤销"
   两个来源写同一列 ⇒ admin 说不清"为什么失效"。必须加列区分（`manual` / `unpublished` / `resume_deleted`）。
2. **`ShareLink.label` / `note`**：多条链接并存时光看 token 无法区分，R4 的列表需要它。

事件模型按设计文档 §12：**可分析维度提升为列**（`revision` / `themeKey` / `targetHost` / `pagePath`），
只把真正自由的放 JSON —— 自由 JSON 无法索引、无法约束、口径随人写。

## 风险

1. **token 强度与限流**：`/share/:token` 是公开端点，token 必须 ≥16 字符随机串，且必须限流；
   否则等同于开放暴力枚举。
2. **引导页的"同意"在技术上有个坑**：HTTP 请求到达时 IP/UA 已被服务器看到。
   要让它有意义，只能在**加载时不写任何访客信息**，等确认后再 `POST /share/:token/ack`。
   代价：没点同意的访问不计入统计。
3. **`indexable` 是新增列**，且**不能与 `isDefault` 隐式联动** ——
   否则切换默认简历时会静默改变 SEO 状态。
4. **取消发布的语义**：派生失效（重新发布会复活旧链接）vs 物化撤销（永久失效）。
   两者都合理，但必须选一个并写进接口文档。

### C 取消（Owner 2026-10-19）

**访客页面不加分享按钮**，包括 `/share/:token` 与 `/resume/:id`。

理由（Owner 的原始设想）：作者分享后，通过链接/二维码进来的访客**只消费**，
想再转发就自己复制当前地址 —— 效果一样，但**不必判断"他有没有权限再分享"**，
省掉一整个权限分支。

这条简化是对的：访客若"再分享"，要么复用同一个 token（把它的触达面扩散到
作者没有预期的范围与期限之外），要么得建新链接（而访客没有建链权限）。
两者都要引入权限判断，而现在**根本不需要**。

### ⚠️ 一个必须说清的矛盾：过期保护的是**链接**，不是**内容**

`/resume/:id` 是公开页：**只要简历已发布，任何知道 id 的人都能永久读到它**
（不需要 token、不受有效期约束）。而 id 是自增、可枚举的。

所以"有效期"实际保护的是**那一条分享链接**（发的出去、到期作废、可撤销），
而不是"这份简历在某时刻之后就不可读了"。

| 若你要的是 | 该怎么做 |
| --- | --- |
| **链接可信、可撤销、可统计**（当前实现） | 现状即可 —— 过期只影响该链接，不宣称内容不可达 |
| **内容在某时刻之后真的不可读** | 需要收紧 `/resume/:id`：只允许读**默认展示**那一份，其余简历一律必须凭 token 访问 |

这一条已写进设计文档 §10；当前按第一种理解实现（与既有 `/resume/:id` 的公开定位一致）。
