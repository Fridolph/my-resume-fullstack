## 为什么

本仓是 monorepo，"维护一处、两端同时生效"是它的初衷。现状却是：

| 现象 | 证据（2026-10-15 实测） |
| --- | --- |
| 公共组件没共享 | `apps/admin/app/components` **48 个 / 5465 行**仍在 app 层；`packages/ui` 只有 5 个组件 |
| 同名实现平行维护 | `cn` 在 `packages/ui/app/lib` 与 `apps/admin/app/utils` 各一份（实现相同、注释不同）；`query-keys` 两端各一份 |
| 工具无处可去 | web 的 `app/utils` 是空的；admin 有 9 个通用工具（number / fileValidation / phoneMetaData…） |
| 分包机制没用起来 | `@rs/ui` 没有 `exports`，只能靠 layer 自动导入；想"显式 import"时无处可去 |

## Owner 定的三件事

1. **导入方式**：继续用 **layer 自动导入**（模板里 `<MyModal />`）；只在需要显式导入处补 `exports`
2. **起步顺序**：**先清重复**（cn / query-keys），再抽组件 —— 改动小、立刻消除漂移，也给后面立样板
3. **utils 落点**：`packages/ui` 收"纯前端工具"（它已经是跨端前端基础层：请求层 `plugins/api.ts` 就在那里）

## 能力叠加约定

ui 组件**只描述"能做什么"，不判断"谁可以做"**：编辑入口是否出现，由宿主经 props / slots / composable 注入。
本仓已在用这三种扩展点：`MySchemaForm` 的 `list-item-extra` 插槽、`MyModal` 的 `footer` 插槽、
`plugins/api.ts` 的 `$api` 注入。展示容器即可按此设计：`editable` prop 或 `#section-actions` 插槽 ——
web 传 `false` 纯展示，admin 传 `true` 注入拖拽编辑。

## 已验证的重要边界（这次踩出来的，必须记）

**Vue 的 `defineProps<整个外部类型>()` 无法跟随包的 re-export 链。**

- 现象：批 1（DAO-034）把展示域类型提到 `@rs/common` 后，web `/resume` 在 **dev** 下 500：
  `ResumeEducationSection.vue — Unresolvable type reference or unsupported built-in utility type`
- 根因：`@rs/common` 的 dist 入口是一串 `export * from './xxx.js'`，**SFC 编译器不展开它**
- **三个信号只有 dev 会报**：`typecheck` 通过（TS 跟随 re-export）、`build` 通过（生产不做运行时 props 推断）
- 对照：`packages/ui` 的 `MySchemaForm` 用同样的 `@rs/common` 类型却没事 —— 它是
  `defineProps<{ …; segments: FormSegmentSchema[] }>()` 这种**内联对象类型**（编译器只解析外层，
  字段引用解析不到会降级）；而 `defineProps<ResumeSectionProps>()` 整个类型都在包外时无处可降
- 修法：**让原引用路径直达源码定义**（layer 的 `nuxt.config` 加 alias 指向 `packages/common/src/resume/content.ts`），
  引用一行不改
- 推论（给后续抽公共组件的提醒）：**组件从 ui 暴露"整块 props 类型"时，消费端要能解析到定义**；
  否则宁可让 props 内联、只让字段引用外部类型

## 环境注意（本轮踩到的）

- **每次 `pnpm install` 后必须重启 dev server**：依赖目录变化会让运行中的 Nuxt/Nest 进程模块解析失效
  （表现为整站 500，但 `typecheck` / `build` 全绿）
- 通过工具启动 dev server 需要 `TMPDIR=<工作区内目录>`：Vite 要建 `/tmp/nuxt-vite-*`，沙箱不允许写 `/tmp`
- `CI=true pnpm install` 会触发 pnpm **重建并删除根 `node_modules`**；加依赖请用 `pnpm install --no-frozen-lockfile`
