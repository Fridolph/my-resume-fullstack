# Harness 实验与开放问题

这里记录“已经发现，但尚未被模板验证”的 Harness 假设。它们不是待办清单，也不是正式规范；每一项都需要通过一个真实任务得到证据或反例。

## EX-001：交接如何回写而不制造污染

- 问题：`dao-handoff` 能生成交接包，但当前还没有确定其最小写回形状。
- 工作假设：任务卡只保留一段“当前交接”，覆盖旧交接；Git 历史保留关键变更，不在卡片累积对话流水。
- 待验证：另一位 AI 是否仅凭当前交接完成第一刀；缺什么字段时才补，不先扩卡。
- 边界：不自动抓取或转存全部聊天记录。

## EX-002：当前状态如何可观察

- 问题：状态若只在聊天中表达，换人后不可追溯；若到处复制又会漂移。
- 工作假设：任务卡 `身份` 区是唯一状态源，`CURRENT.md` 只指向当前任务。
- 待验证：连续三轮任务是否能在不读历史对话的情况下正确恢复状态。
- 边界：v0 不引入看板、数据库或自动状态机。

## EX-003：验证证据怎样记录与量化

- 问题：机器验、结构验、意图验需要证据，但不能把原始日志塞进任务卡。
- 工作假设：任务卡只存命令/样本/链接、结果和未验边界；原始输出留在 CI、测试报告或 Issue。
- 待验证指标：每轮是否列明执行的检查、通过/失败结果和至少一个未验边界；review 接手者能否复现关键验证。
- Human in the loop：Agent 可记录客观命令结果；人确认风险接受、验收口径与 `done`。

## EX-004：集成 Dao Commit 怎样回链

- 问题：集成锚点能描述 `feature -> dev` 或 `dev -> main` 的净变化，但任务、决策和证据无法被一眼关联。
- 工作假设：只有准备合并的集成任务，才在“Git / PR”和“Dao Commit”字段写入 commit SHA、PR 链接或候选标题；不把完整 commit body 复制回来。
- 待验证：数周后能否通过任务卡反查集成净变化、验证依据与最终锚点。
- 边界：日常任务与流程修订只记录常规 commit；本轮不修改 `dao-commit` skill，先积累三条真实集成回链样本再决定是否补协议。

## EX-005：归母候选怎样收集

- 问题：跨项目经验还少，过早建立沉重知识库会制造空壳。
- 工作假设：每张任务卡只允许填写一个简短“沉淀候选”结论；只有 `dao-return-dao` 判断为“候选观察”或“可以归母”时，才新建跨项目对照记录。
- 待验证：两个以上真实项目是否出现同一规则，并且反例与适用边界是否足够清楚。
- 边界：不因为模板仓定义了字段，就自动把经验送回母仓。

## EX-006：质量任务的构建依赖

- 问题：干净环境中，`typecheck` 与 `test` 会先于 `packages/common` 生成 `dist`，导致 `@template/common` 无法解析或测试入口不存在；`build` 后两项通过。
- 结论：已在 `DAO-002` 中通过 Turbo 任务图修复；`typecheck` 增加 workspace 依赖的 `^build`，`@template/common:test` 仅增加自身 `build`，避免无测试 Nuxt 应用被连带构建。
- 验证：清理构建产物后，`pnpm typecheck`、`pnpm test`、`pnpm lint`、`pnpm build` 与 `pnpm format:check` 均通过。
- 边界：这是模板工程健康问题，不是 `DAO-001` 的 Harness 实现范围；在专门任务立卡前不改构建配置。

## 实验纪律

每次只挑一项开放问题进入独立任务卡，并预先写清：假设、可观察指标、额外成本和停止条件。若连续两轮未带来可判断的新信息，应删减字段或暂停该实验，而不是继续加流程。
